# 3.0 local milestone report — 2026-10-14

## Phase 1: inspection and architecture

Cloned official main into the new requested workspace; created branch `3.0`; changed
the development version to `3.0.0-dev`. Inspected Python routes, PKCE/DPAPI login,
archives/taste, content controls, browser cards/navigation and current official Civitai
source. Added architecture/ADR, source references and a report of useful uncommitted
changes in the separate 2.x working tree. Those changes were not imported.

Verified storage before tools/artifacts (about 32 GiB initially available). Disabled
legacy data/credential migration in this development clone, isolated the Linux keyring
namespace too, and reserved a separate loopback port and data directory. No installation,
VM, security setting, release/default branch or old Common Room service was changed.

## Phase 2: contracts and simulator

Implemented API v1, local SQLite adapter, future HTTPS adapter, explicit synthetic
verifier and fail-closed real verifier. Central rules cover identity, ownership, genuine
eligible media, global duplicates, both weekly quotas, timestamps, audit, withdrawals,
moderation, pagination and rate limiting. Added the local privacy wrapper and bounded
upstream transport. Community initialization/failures remain independent of core startup.

**19 automated backend tests passed**, including real-verifier response fixtures,
independent SQLite connections racing for quotas, simultaneous duplicate submissions,
multiple calendar weeks, UTC offsets, no quota refunds, injected failures, all ratings,
hidden metadata, compact-v2 implicit image hides and blocks in both directions.

## Phase 3: UI integration

Added Community Gallery navigation, reused artwork cards, original-artist/member credits,
paste-link verification preview and final confirmation, recommendation actions on
existing cards, quota display, shared browsing settings, pagination and empty/error
states. Added a visibly labeled development entry point and synthetic local images.
Existing personal navigation and actions remain available.

**Playwright journeys passed** against actual isolated loopback servers: preview spends
nothing; confirmation creates a credited card; the card menu uses the same workflow;
duplicate/self/fake/malicious/rating/quota rejections; settings remove filtered cards and
preview metadata; mobile layout stays within its viewport; offline community leaves
personal settings and profile endpoints functional. Desktop/mobile fixture screenshots
were inspected and are kept under ignored `reports/`.

## Phase 4: Supabase readiness

Prepared a PostgreSQL migration, transactional locks/uniqueness/quota RPC, permissions/RLS,
moderation/audit/rate counters, versioned Edge Function, placeholder configuration and
deployment/rollback checklist. Prepared separate PostgreSQL concurrency/permission
tests and a no-quota-spending Edge smoke test for an approved isolated environment.

**Edge transport harness passed** by executing the actual TypeScript handler under
Node 24 with mocked upstream/RPC transport. It checks trusted identities/owners,
preview versus acceptance, input rejection, timeouts, expired credentials and avoiding
OAuth forwarding to public media endpoints. **Strict TypeScript checking passed** using
TypeScript 7.0.2 and a minimal ambient Deno declaration. No runtime SDK dependency was
added. This is not an actual Supabase/Deno deployment test.

**Not run:** real PostgreSQL execution/concurrency/RLS, Deno runtime/gateway behavior,
and authenticated live Civitai integration. The opt-in scripts correctly report SKIP
without explicit isolated-environment configuration. These are required before claiming
production readiness; see `3.0-supabase.md`.

## Phase 5: integration and regression

**All 84 existing regression scripts passed**, including the corrected legacy test,
with targeted rechecks after integration changes. The suite covers daily galleries,
profile analysis, content controls, OAuth storage/refresh/disconnect, archive/SQLite
concurrency, Time Machine, card actions, updater, navigation and browser behavior.
Python compilation and `git diff --check` passed. Detailed generated outputs remain in
ignored `reports/3.0-regression.json` and `reports/3.0-validation.json`.

An initial legacy test failure exposed a hardcoded 8906 port in `seen_creators.py`.
The new server refused to bind it. The old test nevertheless contacted the daily app
for reads and three invalid validation requests, all rejected; it failed before its
first valid mutation. This clone's test now selects an ephemeral port and checks
child-process liveness before readiness; its rerun passed. No accepted daily-app write
was performed. No attempt was made to stop/restart that app or alter its runtime data.

The development instance was successfully launched on `http://127.0.0.1:8907`, explicitly
in fixture mode with isolated `data-dev-3.0`. Health checks confirmed `3.0.0-dev`, a
synthetic member, an empty gallery and three available recommendation slots. The
launcher is `scripts/dev-3.0.ps1`; use the app's Close app control to stop this instance.

## Remaining limitations and next steps

- The production-specific checks above require an approved isolated environment and
  designated Civitai test accounts; no real credentials were accessed or copied.
- Upstream tRPC is an official-source implementation dependency, not a guaranteed stable
  REST contract. Source/schema drift fails closed and must be validated before rollout.
- V1 supports publicly retrievable still images; video/audio community submissions and
  anonymous reads remain deferred. Personal Discovery video behavior is preserved.
- The upstream automatic-capture half-day issue and separate local 2.x fixes are
  documented for review, not silently imported or used to repair existing archives.
- Gallery reads revalidate media, tags and controls. Upstream outages suppress the
  request instead of serving stale previews; production latency/load should be measured
  before deciding on any short-lived verified-metadata cache.
- No cloud resources, public deployment, GitHub push, release publication or default
  branch changes were made. Local development changes are intentionally uncommitted
  for review.
