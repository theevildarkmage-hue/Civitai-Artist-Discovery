## Root causes and bottleneck evidence

1. Hosted `gallery_window` (migration202610240002) chooses `least(3,p_limit)` if
   any candidate in the requested window needs review. Edge reviews at most3
   candidates. This deliberately produces cold pages of3 even when24 requested.
   Local code must not relabel unreviewed rows as eligible or skip hosted admission.
2. `fetchPage` previously waited for status to finish before requesting gallery.
   Each is independently authenticated/admitted; sequential ordering adds a full
   status round trip before any card can appear. This is the measured avoidable
   warm-page bottleneck.
3. Local metadata and thumbnail lanes independently cap3. Slow CDN fetches can
   consequently complete in waves of3. Warm local thumbnails were fast in the
   live sample, so increasing downloads is not justified by that sample.
4. `ArtworkCache.gallery` waits for every returned page item or the4s budget before
   returning JSON. Warm hosted pages may return24; local metadata must all be
   checked before cards render. Cold hosted pages already deliver smaller admitted
   slices through ordinary cursor pagination. No new streaming protocol is added.
5. Cache hits avoid artwork verification. Read-only live cache inspection and
   instrumented source tests do not support redundant local verification as the
   primary warm delay. Hosted policy/read checks intentionally remain fresh.

## Small local correction

`static/ui/community.js::fetchPage` overlaps status and gallery using Promise.all.
It applies policy and creates no cards until BOTH succeed. A failure aborts its
sibling browser request, preserves the original error, and cannot flash eligible
cards through a denied status. The same pager generation, cancellation signal,
refresh UUID and cursor guards remain. Every endpoint still performs server-side
identity/invitation checks. No feed cache or cached-status bypass introduced.

The visible sequence is now parallel admission reads -> complete eligibility for
the returned page -> cards -> bounded thumbnail loading, while existing cursor
pagination progressively requests further admitted pages. No worker/pacing/TTL/
grants/policies/RLS/schema changes. One failed/denied status may now have an already
started sibling gallery read; this bounded extra read is cancelled in the browser
but admitted server work can finish. No unbounded retries or fan-out introduced.
A cold shared content-control cache can likewise receive concurrent reads; no new
production instrumentation claims these are coalesced.
