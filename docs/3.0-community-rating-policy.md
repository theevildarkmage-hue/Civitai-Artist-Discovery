# Community recommendation rating policy

## Eligibility and display

Community submission supports all five provider rating values: `1,2,4,8,16`.
The Edge handler defaults to this set for public review, anonymous artwork checks
and the legacy authenticated verification path. An explicitly configured subset
continues to restrict eligibility; malformed policy configuration fails closed.

Viewer ratings remain local display controls. The local client verifies artwork
and enforces all other hidden-content controls before contacting Community. When
only the rating selection excludes artwork, `/api/community/verify` returns
`previewHidden: true` and an artwork object containing only numeric `id` and
`type`. The browser creates no artwork card, media element or outbound preview
link, and requires the normal explicit confirmation. The submission still sends
only the artwork ID and optional existing idempotency key to Community.

No schema, quota, moderation, identity or credential-storage change is required.
Each viewer's gallery continues to apply its own ratings and other content controls.

## Operations

The Production `COMMUNITY_ALLOWED_RATINGS` setting was changed from `1,2` to
`1,2,4,8,16` on 2026-11-08. Only that setting changed. Preserve it during later
deployments; old preparation/rehearsal scripts describe earlier restricted policy
and must not be used as an authoritative current Production configuration.
Changing the source fallback does not override an existing environment setting.

This service change permits the existing Windows client to verify higher-rated
artwork when its viewing filters already allow that artwork. Submission without
a preview requires the new local Python and browser code, so existing packaged
clients need a future client update for that behavior. The correction is included in the 3.0.1 Windows maintenance release.

## Validation boundaries

The new Edge regression covers five ratings, both media types, verification and
submission using synthetic provider/SQL responses. The local-client regression
uses real SQLite quota/feed behavior with synthetic identities and artwork.
The Chromium regression exercises hidden-preview submission for R/X/XXX images
and videos at desktop and mobile widths, checks explicit confirmation, and verifies
that no hidden preview media is requested and no viewing settings are written.

Read-only hosted previews for R/X/XXX images and videos reached the member quota
check after the policy update. The existing test owner's exhausted quota prevented
successful hosted preview completion; no live recommendation was submitted and no
quota was reset. These checks establish that those live requests passed the rating
gate, rather than claiming end-to-end hosted submission acceptance.
