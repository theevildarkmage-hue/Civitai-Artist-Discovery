# Gallery parity, security validation and publication readiness

This milestone replaces Community's button-driven pagination with the same coordinator
used by Daily. No source from the daily 2.2.1 installation is modified. No Git push,
cloud resource, Supabase deployment or release is part of this milestone.

## Actual source audit

The original inconsistency was in `community.js`: a visible `communityMore` button called
its own `load(true)`, while Daily wired `loadSentinel` to a global IntersectionObserver.
Reusing cards had not shared pagination or tab lifecycle. Returning to Community also
called `load()` unconditionally, clearing all loaded cards after restoring its scroll.

`ui/pagination.js` now owns the shared 800px viewport observer, single-flight promise,
AbortController, stale-request epoch, automatic page budget, retry and exhausted status.
Daily supplies its offset/session adapter; Community supplies its opaque cursor adapter.
Both use `feedback.js` skeletons and errors. Navigating away disconnects each source's
sentinel/mutation observation and aborts its pending page. Community retains accepted
pages/cursor/carousels and resumes from them on return. A failed page waits for explicit
retry; it never silently retries every intersection. Empty filtered pages preserve the
next cursor and a bounded automatic fill; further scroll/wheel/touch/keyboard intent
loads another page instead of draining an entire hidden feed. Repeated server cursors
fail visibly. Appending pages does not reset the grid or call scrollTo.

Startup/restoration can enter Daily without a tab click, so a manual first-page request
also activates its observer. An empty result still paints an exhausted/empty status.
These two cases were caught by Daily and new cross-gallery regressions during extraction.

Ordinary re-entry also refreshes the lightweight quota/status read. An opaque, nonsecret
local process-generation marker detects an externally restarted backend and invalidates
the cached projection then. This re-admits displayed artwork through the existing server
gate instead of leaving cached Community buttons tied to a lost process-local admission
list. The marker carries no account identity, authentication privilege, PID or filesystem
information and is not stored in Supabase. A browser test retains its tab across an actual
disposable server restart and verifies that the projection refreshes. No cloud/authentication
contract or persistent schema was expanded.

| Area | Source result / intentional difference |
| --- | --- |

| Infinite scroll / lazy loading | Same new paging coordinator and existing card observer. Daily uses offset/session ordering; Community uses server cursors and groups each creator's recommendations in one carousel. |
| Images / video | Same artwork fallback/availability and video lifecycle. Community v1 accepts still images only; no Community video submission claim is made. |
| Avatars / links / follows | Same metadata hydration and creator action service. Follow/unfollow now notify matching cached cards across both surfaces; no parallel Community implementation. |
| Reactions / counts | Same account map, batched live hydration and card actions. Mutations notify matching cached cards so a retained other-gallery card cannot show stale selection/counts. Missing live fields retain archive counts. |
| Menus / collections / hide | Same menu/collection/content endpoints and permission gates. Successful artist hiding invalidates the personal gallery projection locally and through the existing broadcast channel. |
| Details / carousel navigation | Same detail dialog, original artist links, generation metadata, tags, arrows, keyboard and video policies. Community chooses its authenticated metadata adapter; cached metadata remains local. |
| Content controls | Same rating/account controls. A change made while Community is open invalidates hidden Daily cards before they can be shown on return. No image/rating decision is trusted merely because a card was cached. |
| Sorting | Daily retains date/model/taste/seen ordering. Community intentionally follows latest accepted recommendation sequence; no copied personal ranking UI is added. |
| Loading / empty / errors | Shared skeletons, page status and retry component. Source-specific quota/authentication messages remain actionable. |

Source-specific remaining code is data adaptation, cursor bookkeeping, creator grouping,
recommendation attribution, quota and the native single-submit modal. Follow, reactions,
menus, details, image/video loading and error rendering are not reimplemented in Community.

## PostgreSQL availability and security boundaries

Native `psql`, `postgres` and `pg_ctl` are absent. Docker Desktop is installed, but the
engine cannot run: the installed WSL distribution returns
`Wsl/Service/CreateInstance/CreateVm/HCS/HCS_E_HYPERV_NOT_INSTALLED` and requests Virtual
Machine Platform/firmware virtualization. The attempted Docker startup was stopped cleanly.
No Windows feature, BIOS setting, production database or paid cloud resource was changed.
**Actual PostgreSQL transactions/RLS were not executed. Those tests remain a release blocker.**

`tests/community_postgres.py` now prepares real independent-connection quota/artist/duplicate
races, replay/audit atomicity, member-scoped keys, actual anon/authenticated session execution,
role escalation, default-deny RLS after temporary rolled-back grants, forged JWT role claims,
UTC session timezone/date-boundary checks and rate-window exhaustion/reset. Cleanup removes
idempotency rows before their referenced ledger rows. These additional cases are unexecuted
here; parsing Python or passing SQLite is not evidence that PostgreSQL policies work.
The historical UTC fixture tests a Sunday/Monday boundary; a live Monday clock transition
still requires a controlled isolated staging exercise, not a production clock parameter.

Identity revocation, ownership and metadata authenticity belong at Edge, before privileged
SQL. The actual TypeScript handler is exercised locally under Node with mocked transport:
independent UserInfo identities, expired/revoked rejection, invalid/unlisted/unscanned/reviewed/
future/video/rating-mismatched artwork, caller identity spoofing, rate-limit response and
idempotency routing. This does not prove live UserInfo revocation, deployed Deno/gateway,
PostgreSQL transactions or real SQL rate counters. Those boundaries remain separate.

The schema still stores only identity/attribution references, recommendation IDs/ownership/
UTC acceptance state, audit, short-lived rate counters and replay keys. No binary/prompt/
profile archive is added. Fresh UserInfo, trusted owner/public/rating verification, three
member/artist slots, global duplicate prevention, server clock, transactional locks and
service-role-only RPCs remain the design. RLS has default deny and no ordinary-role policies;
it deliberately does not implement a second client gallery API. Cold metadata is resolved
through local caches. Remaining production controls include ingress/IP throttling before
random invalid-token work, request/concurrency cost limits, moderation, retention/backup/
restore practice and actual deployed-role tests. No substantial backend redesign or schema
migration was introduced by this UI milestone.

## Disposable native PostgreSQL path

If native PostgreSQL binaries become available, local validation does not require WSL,
Docker or Supabase provisioning. Use a fresh OS temporary cluster and unused loopback port,
never an existing DB connection. The following is a future local procedure, not an executed
test result. Supply the actual installed bin directory; it must contain initdb/pg_ctl/psql.

```powershell
$pgBin = '<PostgreSQL bin directory>'
$pgScratch = Join-Path ([IO.Path]::GetTempPath()) ('cad3-pg-' + [guid]::NewGuid().ToString('N'))
$pgProbe = [Net.Sockets.TcpListener]::new([Net.IPAddress]::Loopback,0)
$pgProbe.Start(); $pgPort = $pgProbe.LocalEndpoint.Port; $pgProbe.Stop()
& (Join-Path $pgBin 'initdb.exe') -D $pgScratch --auth=trust --username=postgres --encoding=UTF8 --locale=C
if ($LASTEXITCODE) { throw 'Disposable initdb failed' }
$pgOldPath = $env:PATH
$pgOldOptIn = $env:CAD_ALLOW_ISOLATED_DB_TESTS
$pgOldUrl = $env:CAD_TEST_DATABASE_URL
$pgOldDatabase = $env:PGDATABASE
try {
  & (Join-Path $pgBin 'pg_ctl.exe') -D $pgScratch -l (Join-Path $pgScratch 'server.log') -o "-h 127.0.0.1 -p $pgPort" -w start
  if ($LASTEXITCODE) { throw 'Disposable PostgreSQL did not start' }
  $env:PATH = $pgBin + [IO.Path]::PathSeparator + $env:PATH
  $env:CAD_ALLOW_ISOLATED_DB_TESTS = '1'
  $env:CAD_TEST_DATABASE_URL = "postgresql://postgres@127.0.0.1:$pgPort/postgres"
  $env:PGDATABASE = $env:CAD_TEST_DATABASE_URL
  'create role anon; create role authenticated; create role service_role bypassrls;' | psql -X -v ON_ERROR_STOP=1
  if ($LASTEXITCODE) { throw 'Disposable role setup failed' }
  psql -X -v ON_ERROR_STOP=1 --single-transaction -f supabase/migrations/202610140001_community_v1.sql -f supabase/migrations/202610150001_submission_idempotency.sql
  if ($LASTEXITCODE) { throw 'Disposable migration failed' }
  python -B tests/community_postgres.py
  if ($LASTEXITCODE) { throw 'Real PostgreSQL security tests failed' }
} finally {
  & (Join-Path $pgBin 'pg_ctl.exe') -D $pgScratch -m fast -w stop
  $env:PATH = $pgOldPath
  $env:CAD_ALLOW_ISOLATED_DB_TESTS = $pgOldOptIn
  $env:CAD_TEST_DATABASE_URL = $pgOldUrl
  $env:PGDATABASE = $pgOldDatabase
}
```

Retain failed-cluster logs under the reported temporary directory for inspection. Do not
substitute a production URL or count these instructions as a passing test. Review idempotency,
role/claim and concurrency output before progressing to an approved Edge staging environment.

## Publication and manual acceptance

The intended remote target remains `development/3.0` in the existing repository. Its old
`c340e63` snapshot is preserved privately; placeholders are corrected using exact name/email
from official commit `c861c21`. See the [publication procedure](3.0-publication.md) for the
history audit, local-first CI strategy and explicit future push commands. Release security
checks are unchanged. No remote branch or repository was created.

1. Open `http://127.0.0.1:8907`; confirm `3.0.0-dev` and the cached signed-in profile.
2. In Daily, select a completed real date shown in Application diagnostics. Scroll to
   load more; open/close details and inspect the existing card menu.
3. Open Community. Confirm its compact toolbar, quota and absence of a Load More button.
   Scroll toward the end: more recommendations arrive automatically, extending existing
   artist carousels. “You're caught up” indicates exhaustion. The small persistent ledger
   may finish in two pages; the disposable pagination browser test exercises four pages.
4. Scroll partway down, switch Daily/Community and return. Ordinary navigation retains
   cards and scroll; Refresh deliberately starts a fresh filtered projection.
5. Inspect shared avatar/profile/follow/reaction/menu/details on desktop and mobile.
   Live follows/reactions spend real account actions; automatic acceptance mutates only
   disposable fixtures. Mocked write tests are not a claim of live social-write validation.
6. Change ratings if you deliberately want to modify the development viewing preference;
   both galleries must respect them, including cached Daily cards on return. Restore your
   preferred settings afterward. Automated control mutations use isolated data only.
7. Open/cancel Recommend Art: one native dialog, one URL/ID input. Live interactive
   submission consumes the simulated member's local quota and performs real verification.
   Automatic quota/duplicate/ownership/replay tests use disposable identities.
8. Run the documented smoke command with `--restart`; it blocks live browser POSTs,
   checks protected session/cache persistence and compares critical data hashes. A failed
   page offers Retry rather than repeatedly requesting in the background.

Exact test results, screenshots, source/publication hashes and before/after data comparisons
are recorded in the local completion report under `reports/parity-2026-10-21/`.
