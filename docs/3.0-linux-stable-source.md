# Stable Community from Linux source

The published Windows ZIP embeds stable Production configuration. Source execution
needs an explicit `--stable` flag; checking out a stable tag by itself does not
select the public service. This flag is available only in source containing the
Linux stable-source fix, not the original immutable v3.0.0 tag.

## Start with uv

From a checkout containing this fix, in a normal Linux desktop session:

```bash
uv run --with-requirements requirements.txt server.py --stable
```

Or install runtime requirements into a virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python server.py --stable
```

Use Python 3.10 or newer compatible with the pinned runtime dependencies. No
Playwright, browser-test dependencies or PyInstaller is needed to run the app.
The browser is the interface to a local server. Keep the server running while using
the app; **Close app** stops it. The default port is 8907; use `--port 8908` if an
older source instance already occupies it. The OAuth callback uses its own fixed
registered port, so complete sign-in with one instance at a time.

The UI should show **v3.0.0**. For a non-sensitive configuration check, the local
`/api/history/config` response should show `channel: stable` and
`environment: production`. Community still has the old visible **Community Beta**
label until the separately tracked branding cleanup; that label does not mean the
backend is Development.

## Keyring and fresh identity

Use a running, unlocked Secret Service provider such as GNOME Keyring in the same
desktop D-Bus session. Runtime requirements install the Python keyring client;
they do not install or unlock the operating-system keyring daemon. If sign-in says
Secret Service is unavailable, configure/unlock the desktop keyring first. Do not
use a plaintext keyring fallback or share token files.

Stable source defaults to `data-production-3.0/` beside the source checkout and
ignores `.data-directory-3.0.json`, which belongs to Development. Its different
resolved path also gives Linux protected storage a separate keyring account.
Sign in normally in this new profile to obtain fresh Production identity/device
enrollment. Existing Development data, credentials, and Community recommendations
are not copied. Account controls/follows/reactions can sync normally after sign-in.

`CIVITAI_HISTORY_DATA_DIR` remains an explicit advanced profile override. Unset it
for the standard isolated launch; do not point it at a Development, old-version,
or concurrently running profile. No automatic archive migration is performed.

## Service selection and errors

`--stable` selects a fixed reviewed release identity and Production project. It
does not accept an arbitrary endpoint. Community uses the hosted backend even if
an old shell has `CAD_COMMUNITY_MODE=local`; fixture mode is rejected. Development
test identities, controls and diagnostic endpoints are unavailable. OAuth API
credentials stay local; the existing signed-identity exchange is unchanged.

Plain `python server.py` retains the existing beta/Development defaults. That
mode can use a local Community ledger with no shared recommendations, which is
why an HTTP 200 response alone does not prove public Community connectivity.

If stable Community asks for fresh authorization, use its reconnect action after
confirming the keyring works. A service outage should not prevent Daily Gallery
use. If the gallery is empty, inspect its content-control message rather than
changing backend files. For support, share app version, environment, and the
visible error; never share credentials, private keys, profile databases or backups.

## Verification boundary

Linux remains experimental. The fix has source-selection, backend-isolation,
signed-out local HTTP and synthetic credential-boundary checks. A passing test
with a mocked Secret Service backend is not a real Linux keyring or OAuth test.
Physical Linux desktop sign-in and Production feed loading require a real user
smoke test before claiming Linux end-to-end acceptance. No hosted activation or
new Windows release is required for this source-launch correction.
