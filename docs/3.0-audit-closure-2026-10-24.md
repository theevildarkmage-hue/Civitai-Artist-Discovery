## Hosted rollout boundary

The reviewed nine-to-ten builder locks migration execution, verifies exact history
and postgres authority, snapshots protected rows and routine authority, applies the
additive migration transactionally and records its exact source in migration
history. Native tests exercise rollback followed by retry. No hosted records or
quotas are reset. A final clean source commit produces the manifest and SQL bundle.

Deployment requires separate owner approval. Apply SQL before the matching Edge
entry point, preserve existing policy/registry/ratings settings and invitations,
and verify catalog and authenticated denial behavior afterward. A failed migration
rolls back atomically; stop on unexpected state. If Edge deployment fails after SQL,
stop and preserve diagnostics. The pinned v28 source is compatible with the added
schema but can show degraded cold reads until the matching handler is restored;
that is not a complete behavior rollback. No destructive down migration is approved.

## Independent audit

Use 3.0-claude-audit-prompt.md with 3.0-claude-audit-access.md. The fixed local helper
has been exercised against staging with read-only authority. It returns catalogs,
function definitions, migration fingerprints and aggregate counts, not credentials
or user rows. It is not an OS sandbox for a program running as the Windows owner.
Official MCP browser authentication is an optional documented alternative and has
not been configured by this task.

## Known limits

The candidate is unsigned. Backup restoration covers the captured Community schema,
data and history in a separate PostgreSQL cluster, with same-Windows-account DPAPI
custody; it does not prove cross-account recovery, Supabase Auth, Storage or hosted
secret restoration. Existing profiles and snapshots are preserved. Linux execution
is waived. No recommendations are submitted by these tests. The broad/native and
exact-package evidence belongs in the private engineering completion report.


## Owner-requested LAN follow-up

The owner rejected the added pairing architecture and explicitly requested exact
2.2.1 LAN behavior. The current implementation restores its direct-IP toggle,
restart confirmation, primary-adapter selection and own-address Host/Origin checks.
No pairing credentials or per-device enrollment remain. LAN intentionally shares
this installation's signed-in profile, as explained by the restored upstream UI.
This supersedes the earlier inert-LAN cleanup and intermediate pairing candidate.
