# Discovery 3.0 — response to the independent adversarial audit

The owner supplied a static audit on 2026-10-24. Its findings are inputs to
verification, not deployment instructions. Beta.5 addresses the high-priority local
request and data-loss defects. The owner subsequently approved publication and the
separate owner-only personal quota exception described in
`3.0-owner-quota-testing.md`; that ninth migration preserves grants, invitations,
ratings, existing data and deployed Edge source. Other hosted findings below still
require their own compatible, tested corrections.

## Confirmed and addressed locally

| Finding | Evidence and correction |
| --- | --- |
| 1: static UNC/drive path before containment | Decoded attacker paths reached Windows path resolution before the containment check. Reject backslashes, colons, empty/dot segments and control characters before any filesystem operation. A trap test asserts that malicious paths never reach `Path.resolve`; no external UNC address is opened. Existing containment remains for valid paths. |
| 2: non-advancing collector | The v1 collection loop trusted the next cursor. Track cursors, stop cycles/repeats, stop after three consecutive empty pages, and cap requests at 1,000 per feed per run. Validate before storing the next checkpoint. Incomplete runs remain incomplete and retain the last good checkpoint. Apply the same protection to reaction pagination with a 10,000-page cap. |
| 3: destructive empty reconciliation | A terminal empty response was treated as authoritative removal of all local rows. Preserve an existing profile on any zero-row result, or a decline below half of at least 20 stored rows. Count unique persisted sync markers, including resumed pages, rather than page totals. Clear a rejected terminal checkpoint so retry re-fetches. Guard follow replacement within its transaction too. First-observed history survives; normal small removals still reconcile. |
| 9: cross-site GET work / unused crawl | Fetch Metadata rejects browser `cross-site` and `same-site` requests before routing; a different localhost port is not same-origin. Keep local non-browser clients compatible. Remove unused `/api/artists`, which could crawl upstream under the write lock. Other legitimate same-origin GET enrichment remains. Bounding `ORDER_CACHE` growth remains a separate follow-up. |
| 11: infinite/huge Retry-After | Both collectors previously reparsed raw values with `float`, bypassing the shared finite parser. Use the finite parser; reject requested delays over ten minutes by stopping with saved progress instead of shortening the upstream delay or waiting indefinitely. The existing shared background-lane lock across ordinary backoff remains a separate scheduling limitation. |
| 12: duplicate block collectors | Hold the reentrant archive lock across status inspection, worker reservation and start. Concurrent starts reserve one worker and one cancellation event. |
| Low: static read errors | Permission/locked-file failures produce a controlled 503 rather than dropping the connection with a traceback. |

Suspicious-snapshot rejection deliberately favors preserving history. A genuine
bulk removal from Civitai can leave stale local rows until an explicit existing
profile reset or a later policy change. No automatic deletion confirmation UI or
new consent interface is introduced. Per-item updates already read can persist
on an incomplete sync, as before; unseen history is not retired.

Fetch Metadata is a browser boundary, not authentication for arbitrary local
processes. Requests without the header remain supported for local automation.
No guarantee is made for obsolete browsers that omit it; the UI already requires
modern browser capabilities. Static-path lexical rejection does not depend on
Fetch Metadata and remains enforced for all callers.

## Verification boundaries

The new adversarial suite uses real temporary SQLite stores and the actual
collector with synthetic upstream pages. It tests no-filesystem resolution,
cursor cycles/caps, preservation after empty/truncated/duplicated responses,
follow preservation, concurrent collection reservation, and finite retry waits.
The HTTP suite uses an actual isolated local server. Neither sends an SMB probe,
extracts existing OAuth credentials, nor writes hosted recommendations.

A fresh hosted read-only catalog check against `aibelmhucizupzvvhdvf` passed
using the automatic eight-migration schema model and expected function v28.
This establishes current catalog assertions, not proof of every runtime attack
or a new function deployment. Full test counts, build provenance and remaining
limitations belong in the private completion report for this task.
