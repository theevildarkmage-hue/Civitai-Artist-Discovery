## Implemented scope

- H-01: reproduce real Windows sharing failure, coordinate protected reads/writes,
  bounded atomic-replace retries, retain successfully rotated grants in memory if
  persistence fails, and prevent redeeming the superseded credential again.
- M-03: fixed diagnostic operations/categories and random correlation identifiers;
  bounded log rotation and deduplication. No arbitrary exception messages, types,
  URLs, headers, bodies, causes, credentials or tracebacks are logged.
- M-01: explicit enrollment states and targeted same-account reconnect with a new
  nonce. Preserve Daily authorization and reject account/client mismatch. Existing
  device renewals remain silent; missing assertions require fresh authorization.
- M-04: coalesce cold gallery metadata, reuse the existing three-worker global
  limit, pace starts, retain checked work for retry and stop waiting after four
  seconds. No stale gallery fallback, skipped ownership/rating gate, cursor
  advancement through partial failure, or hosted admission changes.

## Failures observed and corrected

- Before H-01, the held Windows sharing handle caused protected replacement to
  fail after synthetic provider rotation; the focused test failed before the fix.
- Enrollment validation initially exposed an incomplete synthetic renewal fixture
  and a missing local regex import. The fixture now includes a generated disposable
  device key; malformed timestamp types are rejected. The corrected nine-test
  enrollment suite passes.
- The existing reentry browser test expected the old general sign-in error. It was
  updated to assert targeted reconnect, preserved Daily admission behavior and
  successful subsequent auth-state recovery; desktop/mobile scenarios pass.
- All selected findings were reproduced in code, controlled protocol scenarios or
  measured local execution; none was dismissed as Not Reproducible. Unselected
  audit findings were indexed, not independently reproduced in this task.

## Evidence boundaries and security

Windows tests use actual DPAPI storage, real sharing locks, synthetic credentials
and a child-process reopen. Provider/Cloud responses are simulated. Browser tests
use real Chromium and synthetic HTTP; no owner login was requested or stored
credentials read. Secret canaries in exception messages, dynamic type names,
URLs, headers and nested causes were absent from written logs and handler JSON.
Safe categories remain distinguishable, repeated faults coalesce and logs rotate.

Performance measurements use the actual verifier parser and SQLite with a timed
synthetic transport. Final cold/warm and concurrent measurements are documented in
the implementation notes. They are not observed live Civitai or browser HTTP
timeout rates. No measured local scenario exceeded sixty seconds; blocked metadata
returned a retryable error at about four seconds. A successful page under arbitrary
provider delays is not guaranteed. No broad rate-limit or network outage claim is
made from these tests.

## Persistence and preservation

No hosted reads/mutations, migrations, grants, policies, invitations, quotas or
membership changes were performed. No hosted integrity-hash comparison is claimed.
Protected credential location/format and cache schema remain compatible; only
optional fixed local enrollment status fields were added. Rotated grants remain
memory-only on permanent save failure until a protected write succeeds; forced
exit before durability can still require fresh sign-in.

All test databases/profiles were disposable. Existing user profiles, OAuth
sessions, development/stable databases and running applications were not used.
The original private branch stays at its baseline; all changes are confined to
the isolated Beta 11 worktree. GitHub mutations were limited to approved issue
tracking/labels. Public source, Beta 10 tag/assets and main are unchanged.
