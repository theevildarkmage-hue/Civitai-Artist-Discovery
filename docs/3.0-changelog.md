# Discovery 3.0.1 maintenance candidate

Publication requires separate owner approval. This version retains the Community,
reaction, Time Machine, source-restart and artwork-rating fixes listed in the
[release notes](3.0-stable-release-notes.md). It separates runtime diagnostics
from identity-audit tooling, preserves strict build-output redaction, and supplies
a credential-excluding SQLite backup helper for manual beta recovery. Stable
updater verification is unchanged. The older deep-path IDNA limitation remains
explicit in the installation guide.

## Historical 3.0.0 preparation record

The original record below describes initial launch preparation and does not

# Discovery 3.0.0 changelog

Prepared stable release; publication and public activation require explicit owner
approval. Stable 2.2.1 remains published until that separate action.

- Community is the default signed-in experience, with accepted recommendations
  grouped by artist using the existing Daily Gallery metadata/cache/card pipeline.
- Public access reuses the existing server policy: verified Civitai users need no
  invitation, separate registration or second login. Initial identity exchange
  now persists membership before submission; repeated login refreshes that row.
  The compatible forward SQL correction is deployed in disabled Production;
  public activation and genuine enrollment smoke checks remain pending Publish.
- Ordinary three-per-member and three-per-artist UTC-week quotas, duplicate/self
  rejection, moderation, blocks and seven-day feed eligibility remain enforced.
- Signed identity and rotating device-bound Discovery sessions keep Civitai API
  access/refresh credentials local. Community and Registry remain separately
  controlled; disabled Community does not disable local Daily history.
- Shared rating/hidden-tag gates, carousels, detail enrichment, image fallback and
  existing video playback are retained. Required unknown tag checks fail closed.
- Stable Windows packaging uses the canonical executable/ZIP expected by 2.2.1.
  Beta.13-to-stable graduation uses the separately approved beta.14 bridge. Update
  helpers retain profile data, automatic relaunch and rollback-journal recovery.
- Added current stable privacy, install/upgrade and sequenced launch/disable
  documentation, including the owner-confirmed privacy/deletion contact.
- Restrict credential-bearing diagnostic search to the approved HTTPS origin and
  safe redirects; retain authenticated filtering/pagination/retries. Discard
  unexpected refresh-response identity assertions before local persistence.
- Require the same permanent credential-boundary suite for source and both actual
  frozen release channels, with clean source/EXE provenance checks.
- Startup now uses the existing bounded atomic writer for the local instance
  record, allowing Windows restart while a transient reader holds that file.
- Signed-in startup preserves the correct Sign out control instead of also
  exposing Sign in when the application chrome becomes visible.
