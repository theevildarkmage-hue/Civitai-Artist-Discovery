## Cause and smallest compatible correction

The former temporary index called `Deno.env.set` for owner ID, expiry and registry
state at module load. Supabase's runtime implements that setter as unsupported.
The worker consequently failed before `Deno.serve`; CLI ACTIVE status did not
demonstrate successful startup. Native Deno and the previous Node contract fixture
were insufficient deployment compatibility evidence.

The reviewed acceptance entry is `supabase/functions/community-v1/owner-registry-entry.ts`.
It only calls the existing handler with `ownerOnly:true`, invitation enforcement
and distributed limiting. Supabase project secrets supply configuration, read
through `Deno.env.get`; no runtime environment mutation or credentials are embedded.

One handler condition additionally recognizes `DISCOVERY_REGISTRY_STATE=owner_test`
only when the server entry selected owner-only mode. Normal and older normal
revisions treat this value as disabled. Configuration-only use of the ordinary
`enabled` value would unnecessarily expose the production registration switch to
other revisions. Ordinary production `enabled` behavior is unchanged. The fresh
Civitai UserInfo identity check, strict owner ID, expiry at most thirty minutes,
RLS, RPC privileges, invitation boundary and SQL twelve-hour upsert remain intact.
Community stays disabled, independently of registry acceptance.

## Closure, rollback and failure handling

Do not delete the successful owner record. Preserve its last legitimate timestamp
before any eligibility manipulation and restore it after denied probes. Restore
disabled registry collection and an explicit expired owner deadline with the
supported project-secret operation (or the corresponding secure CLI command):

```text
supabase secrets set DISCOVERY_REGISTRY_STATE=disabled COMMUNITY_OWNER_TEST_EXPIRES_AT=2000-01-01T00:00:00Z --project-ref aibelmhucizupzvvhdvf
supabase functions deploy community-v1 --project-ref aibelmhucizupzvvhdvf --no-verify-jwt --use-api --log-level error --workdir <absolute deployment/rollback>
```

Do not assume a secret update immediately invalidates old worker environments.
Wait until the ORIGINAL acceptance deadline plus sixty seconds, then verify that
an otherwise eligible owner heartbeat cannot write. Preserve/restore the actual
last legitimate timestamp if using the controlled eligibility condition. Verify
untrusted client denials again. Restore the original absent registry setting:

```text
supabase secrets unset DISCOVERY_REGISTRY_STATE --project-ref aibelmhucizupzvvhdvf
```

The owner ID is a noncredential setting. The deadline is deliberately left expired;
this restores safe behavior rather than claiming every prior setting digest is
identical. List this explicit configuration difference in the deployment report.
Verify normal source, actual HTTP startup, disabled policy, registry record count,

Only operational throttle activity and any documented nontransactional sequence
allocation may differ. No grants, RLS, migrations, network allowlists, recommendations,
invitations, GitHub branches or releases may change.

On any operation failure, preserve diagnostics, stop new acceptance mutations and
attempt only this approved safe restoration. If restoration fails, stop and report

perform destructive recovery. Hard expiry remains the independent window bound.
