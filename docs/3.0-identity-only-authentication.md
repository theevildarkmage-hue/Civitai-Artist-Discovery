# Identity-only authentication and anonymous artwork verification

Status: local beta.10 candidate, not deployed or published. Keep automatic minimal
registration and independent Community invitation enforcement; no consent UI.

## Defects and replacement

The prior separate OAuth grant removed write permissions but retained UserRead,
which can expose private account data. Turning registry collection off did not
prevent transmission because authentication happened first. The replacement keeps
all Civitai API access/refresh tokens local. Only a nonce-bound signed identity
assertion enters the cloud exchange; later requests use a Discovery-only credential.
The assertion is not an API access token and is never persisted by the client.

A fresh owner-only standalone provider probe on 2026-10-24 verified real ES256
identity issuance, issuer/audience/nonce/subject, public username lookup, and HTTP
401 from UserInfo and /me when given the assertion as a bearer. No response body,
private content, Supabase request or recommendation write was involved. This was
not a fresh packaged login against the candidate handler.

## Implemented architecture

The production index imports identity-handler.ts, which supplies the trusted
session resolver and anonymous-artwork mode to the shared business handler.
Legacy business-factory defaults and older entry files remain for historical
regressions; they are not a fallback in the new index or prepared deployment.
Deploy only the exact new five-file function bundle (including renewal.ts).

A five-minute HMAC-authenticated challenge binds a random nonce to the fixed
Discovery OAuth client audience. Civitai login uses its normal local OAuth grant
once, with this nonce; there is no second scope-33 grant. ES256 verification uses
only the fixed provider JWKS and exact issuer/audience/nonce, numeric subject,
time bounds and canonical encodings. Embedded keys, private material, bearer claims
and arbitrary key URLs fail closed. JWKS is bounded, coalesced and cached five
minutes; unknown keys cannot force refreshes. Provider failure has ten-second
backoff. Key rotation can therefore cause a bounded fail-closed delay.

The public numeric-ID user lookup supplies username. Atomic exchange stores only
assertion/nonce hashes and a random session hash. Access sessions last twelve hours and renew silently using a rotating, device-bound
Discovery credential. Sign-out revokes the associated device family. No user access/refresh credential reaches Supabase.
SQL session hashes are not Civitai credentials. Six new fixed-search-path
SECURITY DEFINER RPCs are service-role-only; the four FORCE-RLS tables have no
client or direct service-role grants. Expired records are cleaned in bounded batches
on later successful exchanges/renewals; this is not a guaranteed scheduled deletion policy.

Windows DPAPI/Linux Secret Service protect the local Discovery session alongside
existing local OAuth storage. Legacy stored API grants are never used for cloud
requests. Fresh login replaces the old saved grant; explicit sign-out attempts
provider revocation. Existing users are not silently revoked or modified by this
local change. A cloud outage still permits local login and Daily Gallery, without
an insecure fallback. Both collection off and Community disabled cause the challenge
endpoint to return unavailable without provider lookups or session SQL.

Civitai currently issues identity proofs during nonce-bearing authorization-code
exchange, not refresh. A signed-proof enrollment therefore establishes a separate
Discovery device authorization; the existing Civitai refresh grant stays local and
continues independently. Registry remains idempotent,
twelve-hour throttled and independent of invitations. Invitation/block enforcement,
atomic member/artist quotas, duplicate protections and RLS remain unchanged.

## Artwork policy approved by owner

Anonymous retrievability replaces the old strict Public-only metadata test.
Link-accessible unlisted artwork is eligible. There is no operator Civitai key,
no metadata credential environment variable and no tester token fallback.

The exact public image lookup supplies artwork ID, type, rating, post ID, media URL
and uploader name. The public post supplies numeric uploader ID and publication
time. IDs, name, allowed rating, publication date and fixed HTTPS media host are
validated; returned first-100 post items are cross-checked when present. Their
absence is not deletion: large posts may omit the selected item from that preview.
No undocumented availability filter is assumed to work.

Anonymous missing/404/403 artwork produces the existing unavailable review verdict
and bounded cooldown. Disallowed ratings produce the rating verdict; overload,
rate limiting and unexpected anonymous 401 are transient, never user sign-out.
Metadata inconsistencies fail closed. Existing gallery reviews remain bounded to
three candidates, with cursor advancement handled by migration 10. No immediate
provider deletion notification or instant revocation is claimed; cached eligibility
and public API caches create a delay. Weekly quota is not refunded on deletion.

exact baseline migration history (ten versions), execution authority and absence of
candidate tables; snapshots counts/digests of all existing Community/private tables;
adds identity/device tables and RPCs plus the default invite_only configuration
column; verifies original row fields unchanged; records all three versions atomically.
No recommendation, invitation, quota or historical data is rewritten.

Prepare with scripts/prepare-identity-candidate.py --include-community-access
--include-device-renewal into ignored reports. The CLI refuses incomplete bundles. After the
local commit, regenerate the manifest and review all file and SQL hashes. Before
any hosted action separately verify project aibelmhucizupzvvhdvf, actual function
source/version, ten migrations, authority, protected counts/digests and secure backup.
Only new required secret: DISCOVERY_IDENTITY_CHALLENGE_KEY (32 random bytes,
canonical base64url). Generate/store through the approved secure launcher, never
source, argv, logs or plaintext files. Existing Supabase backend credentials remain
server-only. No secret was generated or hosted configuration changed here.

Separate approval is required to apply the pinned atomic three-migration upgrade, provision that
secret and deploy the exact matching handler while preserving policy, registry,
ratings and invitations. Then verify hosted grants/RLS/RPC denial, fresh packaged
owner login, registry idempotency/throttling and anonymous artwork preview without
recommendation commits. Old clients will no longer authenticate after the server
switch: coordinate upgrade and fresh sign-in. Rejecting old credentials server-side
does not prevent old clients transmitting them before upgrade.

On unexpected failure stop. Disable Community and collection through approved
operations; preserve diagnostics and the new credential-rejecting entry. Do not
restore legacy token forwarding as a security rollback. Added tables need no
destructive down migration; old records remain intact.

## Silent renewal implementation and limits

The original local Civitai lifecycle is preserved: Windows DPAPI or Linux Secret
Service, atomic writes, a serialized rotating OAuth refresh grant, two-minute
proactive access refresh and transient-outage recovery. Community errors never
clear that grant or set its reauthentication flag. Daily collection still uses
get_access_token(), not Discovery credentials. No real profile migration is run.

A fresh nonce-bound OIDC exchange may enroll a P-256 public device key bound into
the signed server challenge and accompanied by a proof of private-key possession.
The private key is generated with cryptography and saved only inside existing
OS-protected local storage. The server retains the public key and hashes of the
Discovery-only renewal credentials; none authorize Civitai API access.

Renewal signs purpose, credential hash, durable rotation ID, fresh per-attempt nonce
and timestamp. The server verifies the registered device key, re-reads public
Civitai identity, atomically rotates the credential and re-evaluates Community
access. Invitation/block denial never prevents the independent registry identity
session, but all actual Community operations still enforce that denial. No caller
member ID is accepted. Proof reuse is denied; authenticated old-token reuse with
a different rotation ID revokes the device family and its access sessions.

Persisting the rotation ID before transport permits recovery from a lost success
response or crash. A fresh signed attempt can recover the same next renewal
credential; it receives a new access token rather than reviving an expired one.
The consumed proof cannot be replayed. Concurrent local renewal is single-flight;
network work holds no primary OAuth refresh lock, and protected-store updates merge
the latest primary grant instead of overwriting a concurrent OAuth rotation.
Retries back off 20/40/80/160/300 seconds. Existing access remains usable if still
valid; otherwise Community reports temporary unavailability while Daily continues.

A 30-day idle limit slides only on valid device renewal. The 90-day absolute bound
never slides, so the credential is not permanent. Expiry or explicit device
revocation requires fresh Community authorization while preserving local Civitai
login. The owner can revoke all device families for an account through the private
owner_device_revoke routine; runtime/client roles cannot call it. Local sign-out
revokes its family. No independently verified moderator attribution is claimed.

There is no provider back-channel logout/introspection in this design: a Civitai
OAuth revocation does not automatically notify Supabase. Discovery revocation,
blocks, invitation changes, public identity availability, idle/absolute bounds and
local grant rejection are the available controls. Initial enrollment of legacy
profiles may require one fresh nonce-bearing authorization because their stored
OAuth refresh grant cannot produce an identity-only assertion. This does not
reset or invalidate their existing Daily login. Existing unbound prototype sessions
remain short-lived; the new normal client always requests device enrollment.

Both service switches off suppress initial exchange; already enrolled devices may
renew operational authorization while data features remain disabled. No registry,
recommendation or quota write is thereby enabled. Proof/session expiry cleanup
is bounded on later calls, not a guaranteed timed purge of all device-family rows.

Clock-skew renewal failures are transient (backoff), not a claim of revoked identity.
Simultaneous registry/gallery requests join the same bounded cloud renewal without
holding the local Civitai refresh lock. Operator HMAC rotation must account for
in-flight lost-response recovery; revocation/re-enrollment is the safe incident option.
