# Controlled 2.2.1 integration into Discovery 3.0

**Checkpoint and isolation.** The complete pre-integration source checkpoint is
`6247a28402517e60a24a89ff27a433c5b6ea2ef8`. It preserves 141 modified/new source files,
including AGENTS.md, all Community/persistence/restoration/submission tests, both Supabase
migrations, the Edge handler and deployment preparation. Runtime databases, protected
OAuth records, caches, logs, directory pins, reports and virtual environments were not
staged. Secret-pattern review found no credentials; three machine-path references were
reviewed as historical documentation, with none in application code. The checkpoint tree
was clean before creating `integration/3.0-2.2.1` in the sibling integration worktree.

The integration selectively ports official `5fbd5963b7751150c829916c9e777797511dd13f`
relative to `7e78945`; it is not a merge of upstream release history. The sibling daily
2.2.1 checkout, process, databases and global packages are outside the integration scope.
No push, release, publication, cloud resource or Supabase deployment was performed.

**Implemented behavior and root causes.**

| Component | Defect mechanism / incorporated behavior |
| --- | --- |
| OAuth and social reads | A server-rejected but unexpired bearer previously could not force renewal. Rejected-token-aware locking now shares one rotation; 3.0 still retains omitted scope/refresh fields, cached identity and explicit revoked/transient states. Authorization is not forwarded on redirects. Safe reads have bounded retries; writes are not replayed. |
| Profile metadata | Retry-After supports dates/numbers; transient transport errors remain retryable; failed tag queries no longer become durable successful-empty snapshots. Existing account scoping, complete-listing reconciliation and durable cursors remain. |
| HTTP, diagnostics, updater | Origin must match the request host and port; MIME matching is exact. Local diagnostics are bounded/redacted. Updater backup, stage, executable and receipt destinations are checked before mutation. |
| Capture | Unattended halves previously used full-day bounds and interrupted/suspicious results could look complete. Correct segment bounds and a durable recovery ledger retain retry state and backoff. Explicit historical repair remains uninvoked. |
| Ranking and controls | One request-scoped media/model projection drives representatives, reaction totals, counts and pagination; cache keys include selection. Settings lock the complete read/modify/write. Compact/full rating controls synchronize and anchor correctly. |
| Artwork and video | Bounded HEAD-only status probes distinguish 404/410 from transient/authorization faults. Carousels skip confirmed missing items without deleting archives. Video posters/hints, stalls, retries, focus/hover keyboard behavior and cleanup use shared lifecycle code. |
| 3.0 cached previews | The existing preview adapter called a throwing auth helper, turning missing-session cached gallery reads into HTTP 500. It now uses the existing safe identity helper. Local cache URLs retain CDN availability hints so status checks still work; image assignment remains behind the existing tag/control gate. Dedicated backend/browser regressions cover the composition. |
| Test execution | The upstream AST runner did not register a real __main__ module, so unittest classes were undiscoverable. It now registers/restores the module and reports opt-in skips honestly. New tests retain the fail-closed endpoint guard and disposable roots. |
| Windows environment | A venv redirector's PID differs from the server PID, breaking exact instance ownership checks. Tests/launchers use its base interpreter with private packages first on PYTHONPATH, preserving exact-PID guards and leaving global packages unchanged. |
| Clean-checkout fixtures | Community stress previously required an ignored interactive sample. It now builds a fully synthetic manifest, preserving quota/rating/adversarial scenarios without reading personal data. |

Pillow is pinned to 12.3.0 for runtime and development, retaining the all-platform
thumbnail requirement. The private `.venv-3.0` supplies that version; the global Pillow
12.1.1 used by the daily application is unchanged. Development still uses Python 3.14.3 /
OpenSSL 3.0.18. The ported build preflight refuses a release build below the reviewed
Python 3.14.8 / OpenSSL 3.5.9 thresholds; no interpreter upgrade or package build occurred.

**Conflict resolutions and exclusions.** All six anticipated conflicting files were
reviewed: `.gitignore` retains source allowlists and sensitive-runtime exclusions while
admitting only the two offline video fixtures and availability contract; requirements
retain unconditional Pillow; server routes compose Community authentication/challenges,
personal cached previews and selection; app.js retains 3.0 cached startup/navigation and
Community detail routing; api.js combines abort/timeout handling with Community codes and
cross-tab controls invalidation, including error cleanup; bootstrap retains mountCommunity
and exposes the new rendering/video/filter hooks. Clean textual OAuth/taste/card/filter
combinations also received semantic review.

Community's single modal, attribution, account-scoped control cache, real OAuth gate,
simulated-member diagnostics, idempotency and persistent metadata store remain intact.
Personal media/model filters stay hidden in Community, whose submission contract still
accepts public still images only. Supabase SQL/Edge artifacts, community.py/community_dev.py,
cache.py and paths.py have no integration changes.

Intentionally excluded: wholesale 2.2.1 README/version/release-note replacement,
release-publication script changes, any release execution, automatic historical archive
repair, credential/data transfers, production deployment, new Community features and
replacement of stronger 3.0 authentication persistence with older token-save behavior.
The build and packaged-validator security/license checks were ported as source only.
CONTRIBUTING and development instructions use the guarded combined runner.

**Persistence design and compatibility.** `capture_recovery` is an additive table with
block key, reason, attempt count, restart flag and next-retry timestamp. Creation and
shape validation run inside BEGIN IMMEDIATE and commit together. Incompatible existing
tables raise an error and retain data. Archive user_version remains the artist-index
version; no existing image/day/profile/Community schema is replaced. Regression tests
exercise repeat initialization, concurrent creation, sentinel preservation and rejection
of a conflicting schema. Retry auditing does not delete archive rows. Historical segment
membership repair is an explicit maintenance method, never a startup action.

Before activation, the selected development SQLite databases are backed up within the
same installation's ignored report directory, with the development process stopped.
No database or OAuth record is transferred to the integration worktree. Automatic capture
and update checks retain their existing disabled settings. Production PostgreSQL migrations
are unchanged and unapplied.

Early targeted runs exposed runner discovery/PID issues, an obsolete Community content
selector, and the real missing-session preview defect. They were corrected and rechecked;
early failures remain in local evidence. An undrained diagnostic pipe introduced during
startup investigation was replaced with a file-backed server log. Final browser coverage
uses current controls and exercises both Chromium and Edge for the upstream interaction,
availability and video scenarios.

**Outstanding scope.** Actual PostgreSQL/RLS/concurrency/rollback/rollover and deployed
Edge remain unverified because no isolated runtime/test identity is configured. Real
OAuth expiry/revocation injection, frozen packaging and non-Windows execution are untested.
Live cached-session inspection suppresses incidental mutation POSTs; it verifies genuine
session and cached artwork rendering, not a new public recommendation or complete fresh
profile sync. Public submission checks in automation use explicitly synthetic identities
and metadata. The existing protected profile can remain browsable while its durable
background refresh is incomplete.

Next milestone: provide an isolated PostgreSQL runtime and designated identities, execute
both prepared migrations and actual rule/RLS/concurrency tests, then validate the deployed
Edge boundary in an approved isolated environment. That closes the largest remaining
production-readiness gap before new Community features or deployment are considered.
