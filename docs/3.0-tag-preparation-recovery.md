# 3.0.2 tag preparation recovery — issue #60

## Failure and resulting behavior

Civitai's optional tag reads can return an HTTP-level 404 containing structured
tRPC `NOT_FOUND` results. The transport previously raised before batch decoding,
so a few unavailable representatives blocked an otherwise analyzed gallery.
Optional `None` outcomes also lacked durable storage. Retry selected those same
records again, while successful-work counts remained stuck.

The transport now accepts bounded HTTP-404 envelopes only for optional
`tag.getVotableTags` and `image.get` reads, validates missing-result procedure/status
and code, and retains successful items in mixed batches. Plain/proxy 404s,
unrelated procedures, strict reads, authorization/rate-limit/service errors and
invalid successful tag payloads remain failures. HTTP error streams are closed.

Preparation stores unavailable tag outcomes separately from successful tag analysis.
The UI reports analyzed, unavailable and remaining previews, shows an actionable
error when preparation fails, and retains an honest partial-availability completion
message. It does not claim unavailable previews were analyzed or deleted.

## Persistence and security

The additive `archive_tag_unavailable` table contains account ID, image ID, the
`not_found` reason, UTC observation time and retry-after time. Its composite primary
key prevents one account's visibility outcome suppressing another account's lookup.
Unavailable outcomes expire after 24 hours. Successful tag/seen rows are preserved;
expired unavailable rows are replaced or cleared when that image is retried.

`known` retains its analyzed-count meaning. `processed` includes analyzed plus
currently unavailable outcomes; `pending` and durable coverage govern completion.
An old in-memory `attemptedAll` flag cannot override expired/missing durable outcomes.
Immediate Retry reuses successful and unexpired unavailable work; failures and expired
unavailable work remain eligible. No representative image is replaced and no content
control, availability display gate or social-write authorization is bypassed.

Coverage uses bounded indexed lookups for requested IDs, avoiding whole-cache scans
on every status poll. No archive schema or SQLite user-version changes are required.
Older applications ignore the additional taste-cache table; rollback does not require
deleting it. The original installation and full reserved profile remain untouched.

## Validation

The new `tag_preparation_unavailable` suite has eleven tests covering HTTP-level
all-missing and mixed responses, malformed/non-404/strict/unrelated failures,
invalid/null successes, durable restart/Retry, TTL recovery, account separation,
preservation across interrupted chunks and completion after expired outcomes.
The existing `foryou_preparation_status` browser suite retains its original assertions
and additionally checks partial completion, the recheck message and failed-work counts.
Exact broader-suite results are retained in the private issue-60 validation directory.

Real upstream validation used only an indexed slice of the affected November 10
archive from the verified backup, in a separate small database. It found the documented
4,686 representatives: 4,683 analyzed and three unresolved. One genuine Civitai tag
batch returned HTTP 404; the corrected sweep finished with 4,683 analyzed,
three unavailable, 4,686 processed and zero pending. All 141,745 existing tag rows
were preserved. Reopening the small store and retrying made zero additional upstream
requests. No full database was copied or scanned, no social action was sent, and
the helper refused credential rotation while the interactive app was running.

This validates the real missing-entity transport and persistence against the affected
day. Browser regressions use synthetic HTTP; the full-history packaged UI remains
deferred until the separately identified startup backfill scan is repaired. Final
3.0.2 packaging and complete regression/acceptance gates follow all eight items.
