Target only `aibelmhucizupzvvhdvf` (us-west-2). An application Civitai login, a

No new moderator account or OAuth-token sharing is needed for this audit.

## Local Claude Code: fixed audit helper

Run from this repository in the owner's Windows account:

```powershell
python -B scripts/community-audit-readonly.py --output reports/claude-review/hosted.json
```

This was exercised against hosted staging. It verifies project identity and
`transaction_read_only=on` before collecting the security catalog, Community
function definitions, migration identifiers/hashes, indexes, aggregate table
statistics and counts, and Edge revision metadata. It does not expose an arbitrary
SQL argument, call the writable SQL endpoint, retrieve secret endpoints, dump
user rows, inspect Auth sessions, or give Claude a management token in its
environment. The reviewed external launcher is fingerprint-checked before using
the existing Windows Credential Manager entry inside the helper process.

The resulting JSON is an audit artifact, not a full backup. Keep it in ignored
`reports/`; it includes implementation details and aggregate operational data.
Never upload profile databases, encrypted credential stores, management tokens or
recovery archives as context. The JSON identifies capture time and query hashes;
hosted evidence must not be presented as evidence for an undeployed migration.

This helper is not an OS sandbox: other programs under the same Windows account
can independently read that account's credentials. Claude's audit instructions
must forbid bypassing the helper, editing it to expose credentials, or invoking
general owner-administration/deployment scripts. For a separate machine/account,
use a reviewed JSON export or the independently authenticated MCP option below.

## Optional official Supabase MCP connection

Supabase documents project scoping, a read-only PostgreSQL role, restricted feature
groups and browser OAuth authentication without a PAT. See the
[official Supabase MCP documentation](https://supabase.com/docs/guides/ai-tools/mcp).
For Claude Code, use this deliberately restricted URL:

```powershell
claude mcp add --scope project --transport http discovery-staging-audit "https://mcp.supabase.com/mcp?project_ref=aibelmhucizupzvvhdvf&read_only=true&features=database,docs"
```

Then run `claude /mcp` in a normal terminal and authorize the connection privately
in the browser. This option was documented, not authenticated by Codex. Claude
Code is not currently available on this machine's command path. Do not paste a
management token into its configuration, chat, or command line.

Before auditing, verify the effective URL still has the exact project, read-only
flag and two feature groups. Check advertised tools and query only
`current_user`, `current_database()` and `current_setting('transaction_read_only')`.
Stop on writable authority or an unexpected project. No account-management,
function deployment, secret, storage, branching, or write tool is authorized.
Use the local helper's Edge metadata instead of enabling extra tool groups.

For Claude chat on another machine, a minimized export plus the sanitized source
is sufficient for catalog review. Live MCP authentication remains a separate
owner browser action. Read-only access does not authorize expensive queries, user
enumeration, authentication bypass, recommendations, schema changes or releases.
