# 3.0.2 details navigation ? issue #36

Details now offers Previous/Next and a position indicator for a multi-artwork creator
card. Traversal wraps exactly like the card carousel. Daily, Community and Time Machine
use the shared card adapter; a single artwork or absent card context hides navigation.
The underlying card retains the selected item, gallery DOM and scroll position.
Community credit follows the selected recommendation. Metadata, tags, reaction totals
and outgoing links are reset together and rendered for the selected image only.

The adapter reuses lazy collection loading and the existing content/availability gates.
It does not wait on the preview behind the modal. Serialized moves prevent duplicate
clicks; closing invalidates a pending tag gate before it can change the card. Detail
requests retain AbortController/generation protection. A temporary gate failure leaves
the selected artwork in place with an error and permits retry. No social writes are
introduced, and persistence/authentication schemas are unchanged.

Arrow keys work inside the modal while preserving typing, editable content, media and
other controls that own arrow keys. Escape and native focus return remain intact. A
regression test caught focused-button disabling moving focus outside the modal; focus
is now restored after a completed move without changing scroll. Each move stops the
previous detail player; gallery video remains suspended and sound preferences apply.

Validation used the existing source-test interpreter and `scripts/run_tests.py --only`
with `details_navigation_browser`, `detail_dialog_scroll`, `detail_tags_on_demand`,
`media_keyboard_ui`, `community_detail_acceptance`, `community_shared_browser`,
`community_video_browser`, `video_playback_lifecycle`, `video_recovery_browser`,
`time_machine_videos`, `model_filter_carousel`, `carousel_reaction_state`.
All twelve suites passed after fixing and rerunning the new navigation test. The
expanded mixed-media suite and expanded navigation suite each passed their final
rerun. The original failed focus run remains in local reports. The existing hanging
poster fixture logs Playwright route-cancellation callbacks during teardown but exits
successfully; native decoding and player cleanup assertions pass.

These fixtures use synthetic artwork/transport and isolated data, not live social
writes. Final frozen-UI validation and full release regression follow the remaining
release work. No database migration or profile-copy operation applies to this feature.

Final visual review found that two arrow labels were corrupted into question marks
while staging text through a Windows pipeline. The labels now use ASCII HTML numeric
entities, and the browser regression checks the actual rendered left/right arrows.
The transient checking message uses ASCII punctuation. The details-navigation and
scroll suites passed after this correction. Final live screenshots wait for decoded
image pixels instead of capturing immediately after metadata arrives.
