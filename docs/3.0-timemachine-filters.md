# Time Machine content filters

Time Machine now exposes the shared Filters button. The panel offers browsing
levels and the independent tag, account and artwork switches. These are the
same persisted settings used by Daily Gallery and Community; a change refreshes
the active Time Machine walk or creator-history view.

Time Machine does not implement media-type or generation-model selection.
Those selectors/chips are omitted here, the panel explains their scope, and
the active-filter count excludes those Daily/Community selections. Switching
back restores their controls and selections. Resetting filters in Time Machine
restores PG/PG-13 and the three enabled switches while preserving Daily media
and model choices. Daily-only date/view controls stay hidden.

The missing menu came from `showView()` hiding the whole toolbar for Time
Machine. Server filtering was already implemented for the walk, creator history
and thumbnail authorization. This change keeps those server policies unchanged.

Content-setting changes now invalidate pending walk and creator reads, detach
observers and cancel old card artwork. Delayed replies cannot restore cards
selected under previous settings. Separate request and filter generations let
routine refresh retain unchanged cards without disabling their tag checks.
Priming-poll replies use the same stale-response guard. Switching surfaces
closes the panel so an open Daily panel cannot retain misleading controls.

No schema migration, credential change or archive rewrite applies. Filter-only
refreshes do not advance saved positions; normal scroll progress and existing
hidden-tag stepping retain their established behavior.

Regression suites: `timemachine_filters_http`, `timemachine_filters_browser`,
`time_machine`, `time_machine_ui`, `time_machine_search`, `time_machine_videos`,
`timemachine_thumbnails`, `v2_shared_ui`, `community_filters_browser`.
The new HTTP test exercises actual isolated routes/SQLite with a synthetic
provider mirror across 16 setting combinations; the browser test uses synthetic
responses to verify menu scope, saving, late-reply rejection and mobile layout.
The final completion report separately records packaged real-profile checks.
