# Civitai Discovery 3.0 Beta

## Beta authenticated activity notice

Discovery 3.0 Beta automatically records your verified Civitai account ID, public
username, first-seen and last-seen timestamps, app version, and platform in its
private Supabase registry after server-side identity verification. This supports
beta usage and compatibility monitoring. Activity updates occur at most once every
12 hours. The registry stores no OAuth tokens or browsing history, is not publicly
searchable, and does not grant Community access. To request deletion, contact the
maintainer through [GitHub Issues](https://github.com/theevildarkmage-hue/Civitai-Artist-Discovery/issues)
for general support. Do not post tokens, account details or sensitive deletion/security
requests publicly. A private channel requires owner approval before tester distribution.
Later authenticated use can recreate a deleted registry entry.


Windows beta releases are published as portable ZIPs on GitHub.
Owner-only registry acceptance has passed; hosted collection remains off. Community
access and submissions are controlled separately by the server and require an invitation. GitHub Issues is the approved general contact; the owner is the initial operator.
Routine logs/throttle records have an approved 90-day retention target, not a
claim of implemented cleanup. Private sensitive contact, other retention periods
and recovery custody remain explicit decisions in the bundled guides. Resolve
distribution gates before inviting testers; acceptance is not activation.
Community is limited to five explicitly invited Civitai accounts including the
owner; a public source repository or download link is not access control.

## Security update: beta.4

Update older beta versions and complete a fresh Civitai sign-in before using
Community or registry registration. The app keeps its write-capable Civitai token
local and obtains a separate read-only grant for the hosted service. Existing
profiles without that restricted grant fail closed for hosted operations; Daily
Gallery and stored personal data remain available. Login may briefly visit Civitai
a second time to obtain the narrower grant; it does not create another account.

## Windows portable installation

Use only a separately approved `v3.0.0-beta.N` prerelease from the project's GitHub
repository. Verify the ZIP against its SHA256SUMS and release identity. Extract
the complete `CivitaiDiscoveryBeta` folder into a new writable directory outside
your stable installation. Run `CivitaiDiscoveryBeta.exe`; the `_internal` folder
is required. This is a folder application, not a standalone single-file installer.
No service, registry installation, administrator permission or automatic personal
data import is required. Keep the folder and its `data` directory together.

The beta uses port 8907 by default; stable 2.2.1 remains on 39337. If another beta
instance is running, close only that beta normally or choose a separate port and
data directory. Do not overwrite an existing running development installation.
Stable and beta can coexist, but only one interactive Civitai OAuth callback can
own localhost port 8765 at a time. An OAuth port conflict must be resolved before
login; do not borrow another installation's session.

Sign in through Civitai's browser authorization screen. Windows authorization is
protected by DPAPI. Never paste tokens into issues or send your data folder to
testers. Community credentials are server-side; no management/operator credential
belongs in this application. Registration is automatic in the intended beta client; hosted collection remains
off pending a separate activation decision after completed acceptance. Read the notice above
before installing; see [privacy](3.0-beta-privacy.md).

Authenticated users can see the Community tab without an invitation. Invitation,
expired/revoked access, blocked participation, read-only, maintenance and outage
messages are separate. Daily Gallery remains available independently. The beta points its existing Community connection to reviewed staging,
and connects automatically after sign-in, with no Community opt-in checkbox.
Existing local opt-out files are ignored. Downloading or updating does not grant Community access. No automatic invitation or public activation occurs.

## Updates, rollback and removal

Use Check for Updates for approved beta packages only. The beta selects strict
`v3.x.y-beta.N` prereleases, resolves the tag to the exact release commit, requires
the beta ZIP/digest and checks the packaged identity. Stable releases and other
artifact identities are rejected. Interrupted downloads leave the installed
application unchanged. A replacement failure restores the previous package; data
and unrelated files are preserved. Source/Linux updates use the explicit procedure
in the Linux guide rather than executing downloaded shell scripts.

Before a manual rollback, close the beta, retain a protected backup of its data,
and restore a compatible prior beta package into a separate folder using the same
data only after confirming persistence compatibility. No beta data-schema change
is introduced in this milestone. Never point stable 2.2.1 at beta data as rollback.
To remove the portable application, close it and move its data to protected
storage before removing the executable/runtime folder. Deleting local files does
not delete any separately registered hosted data; contact the owner for that.

No installer or update is distributed automatically. The owner must approve the
final source, packaging results, hosted acceptance and publication checklist.


## Default settings and trusted LAN access

Unset preferences use Large cards, viewed-card dimming on, frequent-poster hiding
at 50/day, automatic recent-day saving every 12 hours with All ratings coverage,
and automatic update checks. Browsing stays PG + PG-13 until explicitly changed.
Explicit saved choices are preserved. Capture starts after Civitai sign-in; its
spread-out schedule and checkpoints survive restart. All ratings saves listing
metadata, not an eager download of full artwork files.

LAN access is optional and off by default. On the computer running Discovery,
open Settings -> Local network access, enable Allow LAN access and restart. Restart safely stops background work; saved collection checkpoints can
resume afterward. Open the private link shown there on your phone or
other device. The link pairs that browser to this PC's signed-in profile; it is
not a separate Civitai login. Keep it private. Links/cookies expire on app restart,
and disabling sharing blocks remote requests immediately. Update/install, OAuth
configuration, shutdown, local-data deletion and network administration remain
available only on the host computer. Sign in on that computer first.

Use only a trusted private IPv4 LAN. HTTP traffic is not encrypted, so a network
observer can capture a pairing capability and session traffic. Do not use public
Wi-Fi, port forwarding, an Internet-facing proxy or expose this listener publicly.
No firewall/router rules are opened automatically. Windows may require allowing
the executable on Private networks; never select Public networks for this purpose.
IPv6, Internet access, a separate per-device identity and TLS are not implemented.
