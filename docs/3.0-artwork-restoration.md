# Real artwork restoration and authenticated Community UI

Engineering completion report, 2026-10-15, branch `3.0`. Development stays on 8907.
No 2.x application changes, credential copying, Civitai mutations, cloud deployment,
push or release. This report supersedes the older welcome-screen simulator workflow.

## Implementation and root causes

The active 3.0 profile was valid and had already synchronized 7,819 reacted-to images
and 511 follows. Its `history` database, however, contained only twelve synthetic
`PersonalFixture` records written by an earlier test harness. Pinning that directory
preserved authentication but also selected its test archive. Daily Gallery correctly
read and ranked those rows; their URLs pointed at the geometric fixture endpoint.
This was contamination of the selected metadata store, not a Civitai image response.

Community had a separate problem: only some sampled records had real preview URLs.
Missing URLs became geometric SVGs. Archive samples also lacked complete tags, so
the privacy filter correctly withheld many entries for a viewer with hidden topics.
The welcome button deliberately bypassed login, and fixture backend routes trusted
the simulated-member selection without requiring the normal desktop OAuth session.

The welcome bypass is removed. Normal Community access now requires protected OAuth
at every route: configuration, gallery, status, verification, submission, details,
member switching and thumbnails. Unusable expired or revoked grants return 401.
Isolated automation uses an explicit nonce and fresh test directory; that mechanism
is refused for the interactive profile. Frozen production cannot enable fixtures.
Simulated members remain solely in the explicit development diagnostics panel.

One completed real day, October 14, was restored additively from the locally indexed
archive: 82,900 public metadata records and 4,964 cached tag inventories containing
152,927 tag rows. The source account matched the existing 3.0 profile. Existing
personalization, reaction weighting, follows, ranking and gallery components remain.
Legacy test records remain on disk but their archive/image routes are excluded from
normal browsing. Saved navigation to a missing/test day falls back to the current
cached real day. An asynchronous startup race that could override an early tab
selection was also fixed.
Overlapping auth-status events could also start two diagnostics configuration loads;
configuration is now serialized, preventing duplicate member selectors after restart.
Verification is also disabled while confirmation and feed refresh are finishing;
an enabled control previously allowed a rapid next click to be silently ignored.

For the original thirty Community recommendations, 23 complete tag inventories were
restored through authenticated, read-only Civitai queries. Three files were absent
from the local archive; public `image.get` records confirmed their IDs and owners
and supplied their actual CDN identifiers. Those exact URLs were restored. No
unrelated images or invented artist names were substituted. Historical simulated
artist keys remain in the immutable development ledger for quota compatibility;
unknown real numeric owner IDs are returned as null, not those simulated keys.

## Architecture, security and tradeoffs

Both source SQLite files were opened immutable/read-only. Restoration inserts public
metadata into the separate 3.0 store, checks account identity and refuses existing
days or conflicting artwork IDs. It does not copy database files or credentials.
The new `metadata_imports` table records provenance. Existing rows are not replaced.

Cards request resized previews through the bounded local cache. Actual browser
inspection showed that some CDN redirects ignore resize parameters. A necessary
fallback may read one response of at most 2 MiB, rejects images exceeding 16 million
pixels or 8,192 pixels on either axis, and caches a WebP preview at most 512 by 1,024.
Only approved Civitai CDN destinations are accepted; no authorization headers or
cookies accompany media downloads. Three downloads can run concurrently. Subsequent
cards use cached previews, rather than repeatedly downloading originals. Controls
are reapplied before bytes are served, and browser responses use `no-store`.
Pillow was already pinned for Windows; the same pin now applies across platforms.
The existing video/poster pipeline is retained, not claimed to share these image bounds.

Community uses the shared Discovery card and normal detail viewer. The compact
header contains Community Gallery, Recommend Art, Refresh and remaining allowance.
Rules, allowance, input, preview and confirmation are in the expanded workflow.
Simulator identity, warnings, cache timestamps and page counts are in collapsed
development diagnostics. Production does not expose that panel. Missing thumbnails
show a neutral explanation; normal operation never substitutes geometric artwork.

Testing uncovered an additional safety defect: one legacy browser test hard-coded
8907, and the transport guard registered the requested port before proving which
port its process actually bound. A fallback server could leave the browser reading
the live review instance. The test mocked its writes; ledger/audit and profile
preservation checks passed. The test now allocates a free port. The guard refuses
occupied ports, validates PID and actual port from the launched directory before
transport, and rejects the interactive profile. The 84-script suite was rerun with
that hardened guard. This corrects the earlier safety claim, rather than assuming
the old registration mechanism guaranteed isolation.

The separate live browser inspection used the actual saved OAuth session and active
8907 profile, with no auth or image-response mocks. After application restart it
rendered real Daily Gallery images and video posters, seven Community artworks and
the shared detail viewer. It inspected image `complete`, `naturalWidth` and actual
decoded dimensions, not merely HTTP success or nonempty URLs. Image previews
were confirmed at width 512; video posters use the established video path. Desktop,
tablet and mobile had no horizontal overflow or JavaScript errors. All current
Community thumbnail responses succeeded. The ledger and audit remained unchanged.

Not rerun: the old bypass-dependent `Stress.browser()` method, superseded by the
new authenticated/ten-member suites and actual-art inspection. Live production
integration and PostgreSQL scripts were invoked but explicitly skipped because no
isolated service/test credentials or disposable database were configured. Linux,
frozen binaries, real interactive login, live refresh-token revocation and a deployed
shared backend were not verified. Mock grant tests do not prove those integrations.
