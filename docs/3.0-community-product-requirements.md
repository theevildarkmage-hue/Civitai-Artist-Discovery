# Community is the primary Discovery 3.0 experience

Community is first/default after verified sign-in or a new browser session.
Refresh preserves the current tab, per the earlier explicit owner instruction.
Invited, uninvited and public-policy users share the same interface. Uninvited
beta users stay on Community with an invitation-required notice; they are not
redirected to Daily. No checkbox, separate membership, connector, API key, or
additional account is required. Restored valid sessions behave the same way.

Automatic registration means the private application registry discovery_users,
not a manually provisioned Community membership. It uses the six disclosed fields,
collection setting and twelve-hour heartbeat. Invitation checks never gate it.
Daily Gallery and local Civitai refresh credentials remain independent.

## Existing policy reused

| Operational setting | Private database access_mode | Effective Community behavior |
| --- | --- | --- |
| disabled, missing or invalid | either | Unavailable; no Community reads/writes |
| enabled | invite_only (default) | Active invitation required |
| read_only | invite_only | Invited members can browse; no submissions |
| enabled | public | All independently verified users can browse/recommend |
| read_only | public | All verified users can browse; no submissions |

Configuration.ready remains a database safety gate; blocks remain authoritative.
The existing Edge operational setting is an upper bound, not a second audience
policy. Only the private owner_access_policy routine can change audience under
project database-owner authority, recording owner-admin action/reason/time. Runtime,
anonymous and authenticated client roles cannot change it. No hosted mode is changed
by this local preparation. Public activation remains separately unapproved.

Migration 12 adds access_mode with invite_only default and updates the shared
assert_member gate, so protected gallery, submission, quota, reports and replay
wrappers all agree. Edge never skips that gate based on a client preference.
Existing invitations, expiration, revocation and records are preserved. Changing
to public admits existing/new verified users without invitations. Public mode
uses the ordinary three-per-UTC-week cap even for the owner; the previously
approved unlimited owner testing exception remains only in invite-only beta.
Artist-wide cap, self/duplicate checks, rating checks, moderation/audit and RLS stay.

## Evidence boundaries

Local native SQL verifies default invitation behavior, revocation/expiry, public
access with no invitation, ordinary and owner quotas, blocks, owner audit and
untrusted policy mutation denials. All fixture changes roll back. Actual desktop/
mobile UI tests simulate identity and HTTP policy for invited, uninvited, public
and public-read-only users, including fresh sign-in transition and refresh.
Existing navigation, package restart/update and Daily evidence is reused where
unchanged; it is not a claim of hosted public activation or real new-user login.

and the identity runbook for device renewal and coordinated rollout.
