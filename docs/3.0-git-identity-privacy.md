# Git identity and publication privacy

Owner commits use the canonical public GitHub login and GitHub-provided noreply identity. Author, committer and annotated-tagger fields are independent. A short name is canonicalized only when correlated to the confirmed owner email; unrelated contributors and ordinary first-name prose are preserved.

Protected personal identifiers are configured in a private, keyed HMAC policy outside Git. No real-name/email mapping, HMAC key or owner-specific fingerprint belongs in source, fixtures, binaries, logs or published evidence. Local maintainers supply `DISCOVERY_IDENTITY_POLICY_FILE` pointing to that private policy; trusted GitHub Actions uses the owner-provisioned `DISCOVERY_IDENTITY_POLICY` secret. Never print either value. Missing, malformed or unavailable policy fails security CLI checks closed. Secret provisioning is a separate owner-approved setup action, not completed by committing this workflow.

Install `python scripts/install-identity-hooks.py --owner` with the external policy configured. The installer preserves the private path only in repository-local Git configuration and installs content-addressed hooks outside the checkout. Windows/WSL routing must refer to the same canonical bundle through an appropriate local adapter. New clones need policy provisioning or maintainer validation; this does not copy with a clone. Do not disable checks to accommodate an old branch.

`python scripts/check-git-identity.py --all` checks full reachable objects/ref names; normal push checks outgoing destination refs and actual added object ranges. Names, normalized separator/Unicode forms, percent/HTML/JSON/hex/base64 forms and contextual local-home accounts are checked. Decoding is bounded, not a claim to detect arbitrary encryption or steganography. A protected-family-name collision in legitimate contributor attribution requires review; never blindly edit a license or source identifier.

Builds run source preflight and decoded-package privacy checks. The release gate runs these checks in addition to credential transport tests. Use `scripts/check-personal-identity.py --text <file>` before publishing logs/reports and `--package <folder>` before archiving a Windows build. Publish console output only through `scripts/run-redacted.py` or after a passing private-policy text scan. Build failures and local evidence remain private until checked; source-control hooks cannot prevent an administrator uploading a file manually.

Runtime packages contain no owner policy or key. They redact generic home paths, email addresses and credential patterns from diagnostics; owner-specific detection also works when the optional local private policy is supplied. Arbitrary natural-language names cannot be universally recognized without that policy. Local logs are private, are not telemetry, and must pass a maintainer publication scan before sharing. Public creator handles, image IDs, approved contact documentation, canonical GitHub URLs/IDs and service routing identifiers are intentional application data.

The Actions job executes only trusted default-branch policy with least privilege; it never checks out or runs PR code with the private policy. Require its status check and verify the actual provider association after deployment. Client hooks and CI complement one another: CI after push cannot undo first exposure, and external clones/forks require coordination. Never reintroduce original-history branches or publish private backups.
