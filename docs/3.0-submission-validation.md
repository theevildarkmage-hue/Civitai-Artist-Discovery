# Submission, API and persistence validation ? October 15, 2026

## Implementation and root causes

Recommend Art and card actions now open one native dialog with one URL/ID field and Submit Recommendation. No expanded form, preview, or second confirmation is required. Card actions prepopulate without sending a request. The server verifies and commits; rejection preserves input and shows a specific error. During submission the input is read-only and Submit is disabled. A successful write refreshes quota/gallery before closing. Browser testing found and fixed a reopen race caused by closing while the gallery refresh was still pending. The native dialog uses content height; inherited artwork-viewer sizing had made it unnecessarily tall on mobile.

Two independent defects caused real-link failures: interactive FixtureVerifier rejected IDs outside its sample catalog, while CivitaiVerifier requested artwork anonymously and received authentication failures. Interactive development now resolves artwork using the existing protected OAuth session on fixed Civitai API hosts. REST confirms the exact image, URL, username and rating; official upstream image.get supplies numeric ownership, public availability, publication, ingestion and moderation evidence; tag.getVotableTags supplies complete controls metadata. Mismatches fail closed. The upstream tRPC procedures are official application interfaces, not a versioned REST compatibility guarantee. See [official REST image reference](https://github.com/civitai/civitai-developer-docs/blob/main/site/reference/images.md) and [OAuth documentation](https://github.com/civitai/civitai/blob/main/docs/auth/oauth-developer-docs.md).

Temporary tRPC failures now map to service unavailability, refresh failures retain authentication-specific errors, and unavailable/ineligible images no longer produce the same vague verification message. The shared controls importer also omitted outgoing blockedUsers and hiddenImagesImplicit; both now participate in personal/shared controls. No settings were weakened. Interactive development now uses the same account-scoped upstream controls cache as real mode and fails closed when a cold controls lookup is unavailable; it cannot fall back to ratings alone before a profile is analyzed.

## Transactions and security

The browser sends only artwork and a random idempotencyKey. Acceptance, audit and member-scoped request-key mapping commit in one SQLite transaction. Concurrent identical keys replay success with current quota, including after restart; changing the image for a used key is invalid. Failures roll back all three records. Existing global image uniqueness protects keyless and post-reload retries. Upstream eligibility is still checked freshly before replay, so replay can fail when artwork becomes unavailable; it cannot create another acceptance.

Production local/Edge operations derive the submitting identity from UserInfo, never request body, query or identity headers. Interactive fixture mode retains its ten explicitly simulated ledger members, but requires the real OAuth session and rejects work owned by that real account too. Packaged builds cannot enable fixture identity. Simulated selection is under My Profile development diagnostics, absent from the gallery. Challenge-authenticated test roots cannot use the interactive profile and have outbound Civitai networking disabled. Spoofed body fields are rejected; identity headers/query values cannot select a member. Normal requests require authentication on every Community route. Port 8906 and 2.x paths remain protected.

A prepared, undeployed PostgreSQL migration adds an RLS-protected idempotency table and service-role-only transactional wrapper around community_submit. It preserves the original member ? artist ? image lock order. The Edge contract forwards the key and authenticated fixed-host verification. No production migration, function or database was deployed.

## Real upstream evidence and limits

Live read-only verification succeeded for IDs 444795, 652730 and 665589 from other creators, and 145572736, 145568271 and 145568178 owned by the authenticated account. Real UserInfo succeeded. Absent IDs 2147483647 and 999999999 returned INVALID_ARTWORK; a much larger syntactically valid ID caused upstream unavailability and remained fail-closed. The actual app verify-only route returned SELF_RECOMMENDATION for owned work and DUPLICATE for an already accepted public work. No local or public recommendations were created during these live checks; no Civitai content was altered. [Live results](../reports/submission-live-civitai.json).

Missing-owner, deleted/inaccessible, expiry, refresh recovery, revocation, timeout and rate-limit fault scenarios used synthetic transports/credentials. No dedicated live test identity was available; the user's grant was never revoked or deliberately expired. These results do not verify real revocation propagation or deployed Edge behavior.

## Metadata integrity

The imported day remains 82,900 real artwork rows; the database contains 82,912 rows including 12 preserved, quarantined synthetic fixtures. Repeat imports previously rejected every existing day; they now accept matching provenance, verify membership/owner/URL consistency, and resume the separate tag phase after interruption. Unrelated existing days or conflicting artwork/incomplete tags fail closed. Existing complete tag inventories are never merged or overwritten. Original metadata sources are opened immutable/read-only. The two stores are not one distributed transaction; matching-provenance retry is the recovery mechanism.

The original restoration included 4,964 tag inventories. The still-running source cache gained additional inventories between audit passes: 215 newly complete inventories / 6,572 tag rows were added without replacing existing snapshots. The final immediate repeat added zero images, inventories or tags. Every pass added zero artwork, and source file size/mtime stayed unchanged within each import. Full destination artwork-row hash stayed unchanged across the final two repeats. Day provenance retains source-path fingerprint and original import time; metadata_import_runs additionally records source file metadata, completion time and each run's increments.

The original 30 recommendations and audit rows match the earlier baseline exactly. Personal data remains 7,819 reacted images, 7,852 reaction rows and 511 follows. [Integrity evidence](../reports/submission-integrity.json).

Production metadata/control/gallery caches keep the established 86,400-second stale/background-refresh behavior, deduplication and failure preservation. Historical archive rows and fixture gallery manifests remain snapshots; this work does not re-download all 82,900 historical images daily. Submission authority never comes from those snapshots.
