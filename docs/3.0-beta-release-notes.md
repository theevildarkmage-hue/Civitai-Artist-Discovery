# Civitai Discovery 3.0 Beta — local candidate notes

Proposed first tag: `v3.0.0-beta.1`. No tag or release has been published and this
candidate must not be distributed before the acceptance gates close.

- Beta-specific title, browser/tray identity, Windows executable/folder and purple
  B icon adapted from the repository's MIT-licensed generated mark.
- Authenticated Community remains visible independently of invitation. Invite-only,
  revoked/expired, blocked, read-only, maintenance and unavailable states are distinct.
- Application-wide registry is independent of Community membership. Fresh Civitai
  UserInfo supplies identity, with consent disclosure, 12-hour activity throttling,
  operator-only aggregates/deletion and default-off collection.
- Prepared Supabase Auth + TOTP operator boundary, private UUID enrollment and
  transactionally enforced moderation/invitation checks. Runtime service credentials
  cannot invoke the Auth operator wrapper. Real hosted enrollment is not complete.
- Shared PostgreSQL request admission limits upstream amplification across function
  instances. It does not limit billed invocations or replace provider monitoring.
- Beta updater rejects stable/wrong-channel packages, verifies tag-to-commit identity
  and checks archive digest plus embedded application identity. Source update tooling
  rejects dirty worktrees and avoids merges, resets and ignored-file overwrite.
- Candidate schema adds versioned registry and Auth operator migrations after the
  unchanged private-beta security migration. Hosted application backup restoration
  was tested in an independent PostgreSQL cluster before any migration.
- Fixed a browser-test race that aborted the valid resumed pagination request;
  production infinite-scroll logic is unchanged.
- Replaced recursive deletion of old update entries with atomic same-volume
  renames, report incomplete rollback explicitly, and make failed unattended
  helpers exit nonzero without a blocking startup dialog.

## Preservation and known limits

Daily Gallery and personal persistence remain separate. No personal database
migration or OAuth-session import is introduced. Stable 2.2.1 is not modified.
Community staging remains disabled until conditional deployment gates pass; no
real hosted recommendation write test is claimed by fixture/native tests.

The Windows candidate is a portable folder ZIP, not a signed installer or a
standalone single-file executable. Real fresh OAuth/hosted beta acceptance remains
blocked on owner interaction and operator enrollment. Linux execution is blocked
by unavailable virtualization in the current environment and is not verified.
Privacy retention/contact and recovery custody require owner decisions before
collection/activation. Review the operations and privacy guides before testing.
