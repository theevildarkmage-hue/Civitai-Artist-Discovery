# Local Community service and removable Test Lab

This milestone runs the production Community handler in Deno 2.9.8, actual
PostgREST 16.5 and a dedicated native PostgreSQL 17.11 cluster. Nothing is deployed.
The normal port 8907 profile keeps its existing SQLite ledger and real saved OAuth
session. Mutation acceptance uses a new disposable PostgreSQL database exclusively.

## Boundaries

The normal desktop sends OAuth server to server to the fixed Community endpoint.
The handler calls fixed Civitai UserInfo and artwork endpoints; only its private
service credential calls PostgREST RPCs. PostgreSQL enforces self-recommendation,
weekly quotas, duplicates, idempotency and accepted audit writes transactionally.
Ordinary roles have no direct table access and default-deny RLS.

`community-v1/index.ts` registers `createCommunityHandler()` from `handler.ts`.
The factory's default transport is native fetch. Production code imports no test
issuer, mapping, fixtures or development identity code. The separate test launcher
`supabase/tests/local_service.ts` injects a transport to a localhost signed-token
issuer and metadata service. Every request between Deno, PostgREST and PostgreSQL
is real HTTP/SQL; it is not the older SQL adapter. Simulated identity tokens are
never sent to Civitai. The optional live probe permits only status/artwork preview,
uses the existing protected OAuth token read-only, and performs no submissions.

The real-metadata Lab replays a bounded public API snapshot. Its ten signed local
subjects map to verified public uploader IDs solely inside this disposable test
service. These are not authenticated sessions belonging to those creators. Signing keys
exist only in memory/child environments; the manager capability and actor configuration
files remain outside the repository. Member tokens expire after 15 minutes and
are minted again on demand. All services bind to 127.0.0.1, with no OS services.

## Ownership and API evidence

Ownership means the Civitai uploader/publisher account, not copyright ownership.
Member identity comes from UserInfo `sub`, cross-checked against `id` when present.
Artwork identity comes from exact `/api/v1/images?imageId=...` and
`/api/trpc/image.get`: `user.id` is authoritative; the returned usernames must agree.
Deleted/unknown owners, mismatched IDs/names, videos, non-public/unscanned/future
artworks and inconsistent ratings are rejected. SQL compares the independently
established numeric member and uploader IDs before persisting. A changed member
display name cannot defeat that comparison. Caller ownership fields are rejected
as INVALID_REQUEST before any write, rather than accepted as overrides.

Public creator avatars came from `user.getCreator` `profilePicture`, and public
tags from `tag.getVotableTags` `id`/`name`. REST supplies post ID, preview URL,
image type, rating and public statistics. Only the small validated subset needed
by existing adapters is cached; no prompts, credentials or private content.
Collection used 62 bounded read-only discovery/profile requests and four batched
tag requests for 40 images. Two creators had no avatar; the shared initial fallback
is retained. Cached public metadata can become stale or be removed upstream.

## Reproduce validation

Use the private environment and portable runtimes installed under LOCALAPPDATA.
The runner validates cluster ownership, applies the three existing migrations to a
new database, repeats SQL security tests, runs the SQL adapter, then actual HTTP and
browser acceptance. It shuts down only its own processes/cluster in normal mode.

```powershell
.\.venv-3.0\Scripts\python.exe -B scripts/validate-postgres.py `
  --bin "$env:LOCALAPPDATA\CAD3Tools\postgresql-17.11-5\pgsql\bin" `
  --repeats 3 `
  --http-deno "$env:LOCALAPPDATA\CAD3Tools\deno-v2.9.8\deno.exe" `
  --http-postgrest "$env:LOCALAPPDATA\CAD3Tools\postgrest-v16.5\postgrest.exe" `
  --output reports/local-community-acceptance
.\.venv-3.0\Scripts\python.exe -B scripts/run_tests.py --timeout 180 --output reports/local-regression
node --experimental-transform-types tests/community_edge.mjs
& "$env:LOCALAPPDATA\CAD3Tools\deno-v2.9.8\deno.exe" check supabase/functions/community-v1/index.ts supabase/tests/local_service.ts
.\.venv-3.0\Scripts\python.exe -B scripts/check-test-lab-exclusion.py
.\.venv-3.0\Scripts\python.exe -B scripts/check-source.py --staged
.\.venv-3.0\Scripts\python.exe -B scripts/dev-smoke.py --restart --output reports/local-smoke
```

Add `--http-live-readonly` to the native command only for a bounded live check using
the selected existing profile's saved OAuth credential. It never refreshes/saves
the token, and never submits a recommendation or social write. The probe documents
the actual HTTP results; local issuer acceptance does not prove live OAuth.

The HTTP suite covers malformed/expired/revoked/forged credentials, direct RPC and
REST denials, RLS after temporary grants, three rounds of quota/duplicate/replay
races, audit-insert rollback, throttles, bounded request bodies, connection pressure,
PostgreSQL interruption/reconnection and actual dump/restore into another fresh
database. Shared browser tests include synthetic edge cases and a separate real
public metadata path. Each scenario checks persisted counts, rather than trusting
only the HTTP response. The native SQL suite covers UTC boundaries; an actual
calendar rollover under a deployed gateway is still a staging exercise.

## Manual Lab

See [the removable module instructions](../dev/community-test-lab/README.md).
Leave a native runner alive with `--manual-test-lab` in addition to the HTTP options.
It completes acceptance, clears only its own public-fixture test rows and starts a
fresh manual Lab. The report's `http/lab-location.json` gives the external connection
file path without including its capability. Keep this runner alive during use.
The manual service credential lasts 24 hours; restart the disposable runner for a
fresh database afterward. Member credentials still expire after 15 minutes.
After closing the verified development app through its Close app control, start:

```powershell
.\.venv-3.0\Scripts\python.exe -B scripts/dev-launcher.py --port 8907 `
  --test-lab-connection '<external connection file from lab-location.json>'
```

My Profile's collapsed Development diagnostics contains a compact Community Test
Lab. Open it, select a member and use **Open isolated session**. Repeat for another
member to compare independent windows. Each has a unique localhost port, browser
origin and external profile directory, while reusing the production gallery,
modal, controls and card components. No real OAuth storage is copied. Close the
member window to return to the normal account. Ownership Verification invokes the
same actual handler/artwork lookup/SQL preview path used by submissions.

## Security changes and deployment gaps

Real PostgREST exposed a defect hidden by the JSON-null mock: RETURNS void throttle
RPCs respond with HTTP 204 and no body. The handler now accepts that exact response.
The desktop status route no longer sends an illegal gallery-only cursor field.
Direct Python development starts now select the same default fixture ledger and
existing public metadata sample as PowerShell starts, preventing an empty offline
view after enabling the Lab. Explicit offline/local/Supabase modes remain supported.
Ingress is bounded to 120 requests per peer/minute, 2048 peer buckets and 16 active
requests per process; the acceptance launcher uses 200 requests per second only to
keep its localhost scenarios bounded. The production SQL per-token/member limits
remain unchanged. Origin headers are rejected, MIME/size checks precede upstream
work, bodies have a five-second read deadline, upstream operations an eight-second
timeout and one-megabyte response cap. Errors and logs do not expose credentials.

These limits are process-local and depend on Deno's actual peer address. A deployed
gateway needs independently verified trusted-proxy/IP policy and shared cost limits.
The Supabase gateway, hosted secrets, deployed role defaults, actual token refresh/
revocation lifecycle, real multi-account recommendation writes and production
backups are not validated here. Do not deploy based solely on local acceptance.
The PostgREST service key remains privileged: its holder can delegate identities.
No new persistent table, SQL migration, dependency or image-hosting service was added.

Evidence for this run lives in ignored `reports/local-service-2026-10-21/`, including
raw per-suite results, sanitized live API checks, screenshots and integrity hashes.
Reports, database files, OAuth storage and private connection files are excluded
from Git. The final engineering report distinguishes real, simulated and untested
boundaries and records the local commit.
