# Windows stable 3.0 candidate: installation and upgrades

Stable 2.2.1 remains the published stable release. The local stable 3.0.0 candidate
is explicitly configured for the separate Production project; the unpublished
beta.14 bridge is a Development preview. Neither is permission to distribute.
Production remains disabled for private owner acceptance. General enrollment is
tested in public mode on disposable infrastructure; its prepared forward database
correction and live smoke must complete in the separately approved
[publication sequence](3.0-public-launch.md). Only a separate owner instruction
containing "Publish" permits activation/publication.

## Package and identity

A stable portable release uses `CivitaiArtistDiscovery/CivitaiArtistDiscovery.exe`;
the beta uses `CivitaiDiscoveryBeta/CivitaiDiscoveryBeta.exe`. Extract the entire
folder, including `_internal`, into a writable location. Do not copy an executable
alone. Keep the portable `data` directory private; it can contain personal profile
data and protected credentials. Never attach it to an issue or release.

Verify the approved ZIP's SHA-256 against the release sums, its release identity,
source commit and provenance before installation. A Development preview must not
be relabeled as a Production release. The application endpoint is a validated
build input, not a setting that can redirect a downloaded build to another project.

## Upgrade paths

The supported paths under controlled acceptance are 2.2.1 to stable 3.0, and
beta.13 to bridge beta.14 to stable 3.0. The bridge is needed for beta-to-stable
channel graduation; do not promise that an older beta recognizes stable directly.
Stable installations reject beta updates. Stable 2.2.1 is not offered prereleases;
a future approved stable 3.0 release is a stable-channel update.

Before upgrading, close the intended application normally and retain a protected
copy of its data with the matching old package. Do not use a running profile in
two installations. Automatic upgrades preserve portable profile data/settings and
retire the beta executable during graduation. Manually created beta shortcuts
must subsequently target the stable executable. The portable package does not
install a Windows service or manage operating-system shortcuts.

Explicitly saved preferences are preserved. Existing incomplete profiles must
not silently enable automatic capture or expand collection beyond the available
saved rating preferences. See the exact compatibility behavior and unresolved
policy boundary in the [readiness guide](3.0-stable-readiness.md).

OAuth secrets remain local and Windows-account protected. Preserving protected
bytes does not prove that a real Civitai grant remains valid or remove the need
for fresh Production identity/device enrollment. Do not import Development cloud
sessions into Production or borrow another installation's credentials.

## Failure and rollback

A failed download or integrity check leaves the installed package unchanged.
Replacement failures use the updater's rollback journal. If replacement is
interrupted, retain staging, `data/update`, and the matching backup; follow the
[matching-helper recovery procedure](3.0-stable-readiness.md#beta-graduation-and-interrupted-updates).
Do not delete an incomplete journal to force another download.

For manual rollback, close the application and restore the compatible old package
and its corresponding protected data copy in an isolated folder. Never use 3.0
data as a 2.2.1 rollback profile without separately established schema compatibility.
Local rollback does not restore Supabase or reverse legitimate Community writes.
Use the [scoped recovery procedure](3.0-recovery.md) for server-side incidents.

## Acceptance before distribution

The operator must verify the exact final package, endpoint, channel/version,
clean startup, automatic updater relaunch, restart/profile preservation, Daily
Gallery and fresh Production authentication/session renewal. Windows unsigned
executables may display SmartScreen warnings; do not claim code signing.
Keep Linux's experimental/owner-waived status explicit.

Read the bundled [stable privacy notice](3.0-privacy.md) before installing. General support
uses GitHub Issues; never post secrets or sensitive privacy requests publicly.
Privacy/data deletion uses the owner-confirmed theevildarkmage@gmail.com; security
uses GitHub private vulnerability reporting. Backup/retention and provider recovery
boundaries remain documented in the [Production handoff](3.0-production-handoff.md).
