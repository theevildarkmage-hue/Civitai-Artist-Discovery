## Hosted role inventory correction

PostgreSQL automatically grants a newly created role back to a non-superuser
creator with ADMIN TRUE, INHERIT FALSE, SET FALSE. On this project the inert
community_operator group has that owner-only grant to postgres; the existing
Supabase-managed cli_login_postgres role is a member of postgres. The old recursive
inventory wrongly traversed through the infrastructure owner and classified that
CLI login as a restricted application moderator. Inventory now stops traversal at
the verified infrastructure owner while retaining all ordinary-role ACL checks.
Ordinary anon/authenticated/service_role memberships must be empty, so owner-role
membership can never be excused for an application principal. No hosted grant is
changed to resolve this verifier defect.
