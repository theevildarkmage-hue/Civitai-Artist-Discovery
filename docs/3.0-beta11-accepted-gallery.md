# Beta 11: one Gallery, two artwork-list sources

**Community Gallery must use the existing Daily Gallery artwork-processing and presentation pipeline. Its only alternate input is the Supabase recommendation list.**

Supabase enforces identity, invitations, atomic submission/member/artist quotas, duplicates/replay, original 168-hour acceptance expiry, withdrawal, moderation and Community blocks. The service-only recommendation-list RPC filters these before stable seq-desc cursor pagination. Beta11 explicitly requests50; older omitted requests default24. No hosted tag acquisition, snapshots, revalidation leases or metadata backfill are needed.

The local app receives IDs and attribution immediately. The minimal adapter resolves IDs through HistoryArchive.gallery_images: existing shared images cache, authenticated SocialClient batch transport, Daily normalize_hit/_row_item formatting, and metadata-only inserts that never create daily block memberships or overwrite existing cache rows. Small metadata batches render progressively, independently of the up-to50 logical recommendation page.

Both tabs use the same imported TASTE preferences, authenticated ensure_image_tags_many cache, checkImageTags preview gate, createCreatorCard, IntersectionObserver, artwork/video loaders, thumbnail cache, error handling and release hooks. Unknown required tag checks fail closed with a retry. Account changes invalidate pending tag responses and admission; malformed or account-switched preference imports cannot replace controls.

Civitai OAuth credentials remain local. Supabase receives only Discovery sessions and recommendation operations. No local preferences or tag inventories are sent to Supabase. Shared local metadata is public artwork data; Community IDs never enter the Daily collection workflow.
