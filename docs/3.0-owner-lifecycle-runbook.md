# Owner-only hosted lifecycle window

Scope: separately authorized staging project `aibelmhucizupzvvhdvf` only.
This runbook never authorizes a public beta or database cleanup.

The production entry point fixes `ownerOnly:true`. After fresh fixed-host Civitai
UserInfo, the handler compares the verified member ID against the canonical
`COMMUNITY_TEST_OWNER_ID` server setting, before content/quota/write RPCs.
Nonmatching identities receive FORBIDDEN. Missing or malformed configuration fails
closed. Request body, query and header fields cannot configure the gate.

Only `COMMUNITY_BETA_STATE=owner_test` with a future UTC
`COMMUNITY_OWNER_TEST_EXPIRES_AT` no more than 30 minutes away permits the owner
to submit. Even `enabled` cannot activate public submissions in this entry point.
Use a 20-minute window. Ratings remain `1,2`. Generic factory behavior used by the
isolated local service remains unchanged unless its caller selects ownerOnly.

Before activation: verify migration/source hashes and hosted ACL/RLS; obtain fresh
owner OAuth without reading saved sessions; verify owner ID and five real eligible
artworks; pin all public artwork/uploader IDs and ratings in the ignored manifest.
Deploy only index.ts/handler.ts while disabled. Prove the server ID mismatch using
the authorized owner's real token against an intentionally different allowlist ID
WHILE DISABLED; no other account is enabled. Restore the verified owner ID, still
disabled. Combine this live comparison check with local non-owner active-window
tests; do not claim a real second-account login occurred.

After gate verification, activate only owner_test. Run self rejection; three keyed
accepted recommendations from different external artists; fourth-image member
quota rejection; same-key replay and new-key duplicate; two concurrent existing-key
replays; missing/invalid auth rejection. Compare recommendation/audit/replay counts,
verified attribution and current UTC-week usage after every stage. Never reset a
quota or use a privileged RPC to manufacture accepted evidence.

Rollback on success OR failure: set COMMUNITY_BETA_STATE=disabled and the test expiry
to a past UTC timestamp. Verify policy digests and a valid owner gallery response
BETA_DISABLED. Leave the hardcoded owner restriction deployed and the expired test
configuration inert; removing that code is a separate reviewed deployment. Preserve
accepted staging recommendations/audits/replay rows. No destructive down migration,
grant changes, credential broadening or table truncation is permitted here.

If disabled propagation cannot be confirmed, report it immediately; do not claim
cleanup succeeded or perform an unapproved privilege change. Automatic expiry is an
additional bound, not a substitute for restoring and verifying disabled mode.
