# 3.0.2 content-control toggles — reviewed PR #12

Reviewed the complete twenty-file proposed diff and discussions at head
`e925a5cd1ab8f1be0cfa979cb27fad6b650d8d30`. The independent switches, provenance
recovery, Time Machine integration, linear implicit-vote indexing and browser save
handling are integrated with explicit compatibility and persistence repairs.
Unrelated fork enhancements are excluded.

## Defaults and policy adaptation

Tag, account and artwork switches default on and persist in the existing settings
file. Reset restores them. Pausing a switch changes local viewing only: it does not
edit Civitai preferences, remove imported controls or bypass browsing-level checks,
upstream access restrictions or hosted authorization.

The proposal still changed default-on filtering for inactive known-tag votes and
rating votes already within selected levels. Those changes were not accepted.
With tag and artwork switches both on, all active implicit hides remain excluded;
imported hidden tags retain their existing interpretation even when they carry
rating metadata. A reference-evaluator regression compares prior and current
default decisions for direct hides, active/inactive votes, rating votes, unknown
sources, hidden/blocked accounts, unknown tags and browsing levels. Refreshed and
reopened Daily mirrors are checked as well. Proposed tests expecting the unapproved
interpretation change were adjusted to this explicit compatibility contract; the
original compact/unknown-source fixture and earlier assertions remain intact.

When a switch is explicitly paused, known provenance permits its independent
behavior. Unknown-source legacy hides remain conservative until a complete read-only
preference import recovers their source. Recovery is asynchronous, single-flight and
limited to one attempt per five minutes. Outages preserve cached mirrors. A thread
start failure also preserves cached reads instead of breaking the gallery.

## Persistence, concurrency and architecture

Provenance uses an additional JSON value in existing `sync_state`; no new preference
table or archive schema migration is introduced. Preference import retains the full
source rows needed to reconstruct exclusions. Time Machine cards and creator history
receive the same switches/exclusions as Daily and Community, preserving saved artwork
and progress positions. Implicit vote pairs are indexed once per profile; an 8,000-row
work-count regression guards against the previous quadratic scan.

A new two-tab browser regression reproduced a further defect: a delayed rating-save
response broadcast obsolete toggle values after a newer toggle save had persisted.
The receiving tab now treats notifications as a request to read current settings;
generation checks prevent older read results replacing newer ones. This adds a small
GET per settings notification, without mutation replay or a persistent revision field.
If readback fails, the old notification snapshot is not applied. Rejected saves roll
back from readback, and lost replies are reconciled without resending the write.

The earlier auth/session controller, tag-preparation recovery and follower policy
were preserved while resolving the proposal's startup and Time Machine conflicts.
No credentials, social-write gates or hosted services are changed by this integration.

## Validation and limits

New regressions cover default-on compatibility, cached/offline provenance recovery,
thread failure, account changes, large-input work bounds, settings persistence,
cross-tab stale replies, rejected saves and lost responses. Existing Daily, Community,
Time Machine, content-level, preview/detail, capture, authentication, video and prior
P0 suites run against the integrated source. Private receipts retain commands/results.

One genuine Civitai preference GET was also validated in a separate small local store:
147 creator exclusions, 117 tag exclusions and one direct image exclusion were imported.
Default-on image/tag decisions matched the prior evaluator, switches could be paused
and restored, and imported rules remained intact. No real filtered artwork was shown,
no preferences or social actions were written upstream, and no full database was copied
or scanned. Offline and browser failure injection remains simulated, rather than an
assertion that an actual Civitai outage was induced. Full packaged acceptance follows
the remaining sequential release items and the large-archive startup repair.

Full-suite follow-up: the personal thumbnail handler indexed the new applyTagFilters
key directly, so a legacy-shaped/partial settings provider produced 503 before a
valid preview or filtered denial. Normal AppSettings.load supplies defaults, but the
handler now also uses a conservative local fallback: only literal False pauses tags.
One settings snapshot is used per request. The existing thumbnail fixture and all
its security assertions remain unchanged; an additional test covers False, True,
None and numeric zero, and proves paused tags still enforce account/image/rating
restrictions. timemachine_thumbnails (five cases), content_filter_toggles_http and
content_controls_default_compatibility passed. No data migration applies.
