# Public source-launch fix and user notice — November 6, 2026

## Implementation and causes

Issue #32's source fix adds explicit stable Production selection for Linux and
Windows source users. The stable v3.0.0 tag originally used beta.14 identity
defaults and a local Community ledger in unfrozen execution. The published
Windows ZIP already embeds the correct Production configuration.

Added a source-only, server-rendered notice to remove the ambiguity before sign-in.
Development source explains that its Community is separate and displays the exact
`uv run --with-requirements requirements.txt server.py --stable` command plus the
plain-Python alternative. Stable source confirms that public Community is selected.
Neither message asserts that authentication has already completed. Packaged builds
render no source notice. Static text includes no profile paths, identities or
credentials; CSS supports wrapping and small screens. No selection or auth change
occurs merely because a notice is rendered.

README and setup instructions direct source users to current main or
development/3.0, preserving the immutable v3.0.0 tag. Updated the stale installation
introduction to describe the already-published Windows release accurately.

## Architecture and integrity

Stable source uses a fixed reviewed endpoint and separate default local profile;
the original Development path remains available explicitly by omitting --stable.
Protected storage and signed identity remain unchanged. Existing profile overrides
are advanced user controls and must not be used to share a running or Development
profile with Production. No automatic archive/credential migration or schema change.

Publication is source-only: merge PR #33, advance current 3.0 source branches, and
bring the default main branch forward from its obsolete 2.2.1 source tip through
normal history-preserving updates. No force push or tag rewrite. Release ZIPs,
checksums and update metadata are preserved; no hosted deployment or feature-state
change is part of this publication.
