# Launch and test Discovery 3.0

Community now uses Daily's shared card/account services and artist carousels. See the
[current parity/security report](3.0-parity-readiness.md) for automatic scrolling, test
boundaries and manual acceptance. The [native PostgreSQL procedure](3.0-native-postgres.md)
supersedes that report's historical SQL-tool limitation. See the
[unification report](3.0-gallery-unification.md) for boundaries, cleanup and limitations,
and the [publication procedure](3.0-publication.md) before preparing any remote update.
Private branch `3.0` retains recovery history and must not be pushed; the separately
audited local `development/3.0` candidate is intended for future authorized publication.

## Ready for hands-on testing

Start or reuse the verified instance with `powershell -NoProfile -File scripts/dev-3.0.ps1`.
Add `-NoBrowser` to reuse/start without opening another tab. The launcher verifies this
Git checkout, its private Python/Pillow, the pinned profile, process ownership and the
actual listener before reuse; it never terminates an unrelated process. For a different
Community mode, close the current app through its own UI before relaunching. Startup
errors identify the OS temporary startup log and do not launch a competing fallback.

Open **Settings cog → Development diagnostics** or **My Profile → Application diagnostics**.
Expand the panel for a cached snapshot; **Run Diagnostics** adds two bounded unauthenticated
HEAD probes. Counts, controls, metadata freshness, sync state and sanitized recent errors
are read-only. Git commit is captured when the server starts. These tools are absent
unless CAD_DEVELOPMENT is enabled, are always absent from frozen builds, and retain the
test-instance challenge in automation. A reachable API response is not proof of OAuth
authorization or current artwork eligibility.

```powershell
# Full smoke: read-only real profile plus mutations only in isolated synthetic backends.
.\.venv-3.0\Scripts\python.exe scripts/dev-smoke.py --restart

# Read-only inventory; never deletes old data or test directories.
python scripts/audit-workspace.py

# Local source/credential path gate; install the staged pre-commit variant locally.
python scripts/check-source.py
git config core.hooksPath .githooks
```

The combined runner and smoke command print the artifact directory under OS TEMP.
Per-suite scratch profiles, databases and subprocesses are scoped to that suite and cleaned
after process exit, including failures. Screenshots and summaries are retained separately
under the reported validation/smoke directory. Historical workspace test directories are
inventoried for approval and are never automatically removed.

Manual acceptance: open a saved real Daily day; scroll Community toward its end; open and
cancel Recommend Art; compare shared rating controls; inspect cached profile metrics;
restart through the app or smoke command; check diagnostics for the same profile/counts.
Interactive recommendations spend the selected local simulated member's quota and use
real read-only Civitai verification. Automatic submission/quota checks belong to the smoke
command's disposable backends, never the persistent review profile.

## Controlled 2.2.1 integration

The October 21 integration retains `3.0.0-dev`, the pinned development profile,
loopback port 8907, the single-modal Community workflow and production authentication.
The development and verified-checkout restart launchers prefer private 3.0 packages
when `.venv-3.0` exists. They run the base interpreter with that environment's site
packages first on PYTHONPATH so Windows venv redirector PIDs cannot break instance
ownership checks. This does not upgrade the Python/Pillow used by the daily application.

```powershell
python -m venv --system-site-packages .venv-3.0
.\.venv-3.0\Scripts\python.exe -m pip install --only-binary=:all: pillow==12.3.0
.\.venv-3.0\Scripts\python.exe scripts/run_tests.py
node --experimental-transform-types tests/community_edge.mjs
```

The runner excludes import-only helpers, reports opt-in PostgreSQL/Edge skips as skips,
registers unittest modules correctly, and relocates test ports under the existing
fail-closed endpoint guard. Community stress fixtures are generated entirely from the
synthetic catalog; a clean checkout no longer needs the interactive sample cache.
Actual PostgreSQL/RLS and deployed Edge validation are still separate opt-in checks.

Personal galleries gain media/model-aware ranking, bounded availability probes, video
recovery and corrected compact rating controls. Community continues to accept still
images only; its toolbar hides personal media/model filters and applies the same shared
rating and account controls. Cached personal previews retain CDN status hints so an
unavailable cached source can be classified without bypassing the display/tag gate.

The archive adds only `capture_recovery`, in an explicit immediate transaction with
schema validation. It does not change archive `user_version`, delete artwork, or run
historical segment repair. Automatic capture remains governed by the existing setting.
Never run `repair_full_day_segment_memberships` without a separate reviewed maintenance
plan and verified backup; ordinary startup never calls it.

Run from the separate `Civitai-Artist-Discovery-3.0` clone on branch `3.0`.
The initial data root is `data-dev-3.0` beside this clone. A local, ignored
`.data-directory-3.0.json` pins subsequent launcher and direct Python starts to the
same workspace directory; this workstation pins `data-test-community`, preserving
its existing protected session and recommendations. `-DataDirectory` explicitly
selects another directory without merging either profile. Old LocalAppData data and
credentials are never migrated. Ports 8906, 33101 and 33201 are explicitly refused by
the development server. The existing registered OAuth callback port 8765 remains
reserved; do not run simultaneous login flows in 2.x and 3.0.

```powershell
# Simulated local Community ledger; interactive artwork checks use read-only Civitai OAuth.
.\scripts\dev-3.0.ps1

# No tray or browser window (use http://127.0.0.1:8907 yourself).
.\scripts\dev-3.0.ps1 -NoBrowser

# Real Civitai verification, but community records still stay in separate local SQLite.
# Sign in through the existing PKCE UI; no credentials are imported from 2.x.
.\scripts\dev-3.0.ps1 -RealVerification

# Exercise community outage handling without changing personal data.
.\scripts\dev-3.0.ps1 -Offline
```

The simulator needs no new Python dependency. The existing optional Windows tray uses
the project's Pillow/pystray dependencies; `-NoBrowser` avoids the tray. Existing
Playwright/Chromium were available on the development machine, so no browser download,
Docker installation, VM or Supabase stack was needed. Initial free storage was roughly
32 GiB. Check available storage before adding tools/builds.

## Synthetic universe

The launcher sets **both** `CAD_DEVELOPMENT=1` and `CAD_COMMUNITY_MODE=fixture`.
Fixture identity cannot be enabled with only the backend mode. This is development-only;
production Edge Functions contain no fixture identity path.

Sign in normally; there is no welcome-screen bypass. All Community routes, including
config, media, details and member switching, require a usable protected OAuth session.
The collapsed **Development diagnostics** panel under **My Profile** contains the simulated member selector; the gallery has no developer controls.
Only a new, explicitly challenged automation sandbox can substitute test authentication.
The selected interactive profile is refused by both the test transport and server-side
automation gate. Packaged production cannot enable fixture identities.

Simulated recommendations use `DemoMember01`. Isolated automation includes twelve artists,
60 artwork IDs (1001–1060), all five ratings, tag IDs/names and a self-owned ID 1099.
Each group of five artwork IDs belongs to one artist; ratings are PG, PG-13, R, X, XXX.
IDs 1001, 1006 and 1011 are PG artworks from different artists. The initial gallery is
empty; open Recommend Art and submit once to populate it. ID 1099 exercises self-rejection.
Automation refuses unrecognized IDs and cannot contact Civitai. Interactive development verifies real IDs freshly through the protected OAuth session, including IDs outside the sample catalog. It also rejects artwork owned by the real authenticated account, independently of the selected simulated member.

Built-in synthetic artists and SVG images are available only in explicit automation.
They cannot populate normal personal or Community galleries. When a local `sample.json` is
present, the launcher also loads the existing public metadata sample. Usable real
previews use the shared resize transform, a persistent local thumbnail cache, and
current viewer controls. Samples without complete tags are withheld when the viewer
hides topics. `sample-community.py --enrich-tags` adds only bounded public tag
inventories to existing sample rows using read-only source queries; it never copies
credentials or databases. Synthetic and unavailable artwork retains the existing
card fallback behavior. The normal development gallery uses actual public artist
names, artwork IDs and thumbnails. Unknown numeric artist IDs remain unknown in API
responses, rather than exposing historical simulator keys as real Civitai IDs.

Image previews use the pinned Pillow dependency on all platforms. The cache requests
512-pixel CDN previews; when the CDN ignores resizing, a size-limited response can
be downscaled once and cached. Original images are not repeatedly sent to cards.
Existing video playback and poster behavior remains in the shared video component.

`FixtureVerifier.failure` injects `UNAVAILABLE`, `AUTH_EXPIRED` or `RATE_LIMITED` in
backend tests. Removing an item from its fixture map simulates deleted artwork. Injected
backend clocks test multiple UTC weeks and offset boundaries. These controls exist only
in Python test fixtures, not as browser parameters or production HTTP endpoints.

## Verification commands

```powershell
python tests/community_backend.py
python tests/community_browser.py
python tests/persistence_cache.py
python tests/persistence_browser.py
python tests/artwork_restoration.py
python tests/community_safety.py
python tests/community_ten_members.py
node --experimental-transform-types tests/community_edge.mjs
python tests/data_location.py
python tests/seen_creators.py

# Full existing script suite; scripts create isolated test data.
Get-ChildItem tests\*.py | ForEach-Object {
  python $_.FullName
  if ($LASTEXITCODE) { throw "Test failed: $($_.Name)" }
}
```

`community_postgres.py` and `community_production.py` explicitly skip unless their
isolated-environment opt-in variables are set. See the deployment/testing document.
The Node test uses Node 24's experimental TypeScript transform to execute the actual
Edge handler with transport fixtures. It does not deploy anything or validate SQL.

The legacy `seen_creators.py` test previously hardcoded 8906. This clone now chooses an
ephemeral loopback port and checks child-process liveness before readiness. Test
artifacts, synthetic databases, screenshots and reports remain ignored by Git.

Stop the development instance with its **Close app** button. The launcher returns after readiness. Do not
stop a process merely because it is a Python/Discovery process; identify this clone's
isolated data root and port. No old VM or Common Room service is involved.
