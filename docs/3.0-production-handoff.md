## Release and daily operator checklist

Before publication, verify source is clean, full gate receipts match it, package
identity matches the full immutable 40-character GitHub target SHA, and the exact
ZIP/digest is approved. Stable releases are non-prereleases; bridge betas are
prereleases. Publish neither test-only ZIP wrappers nor private reports/backups.
Keep published 2.2.1 and existing beta data intact. See the
[installation and rollback guide](3.0-stable-installation.md).

The owner reviews reports/blocks, service errors, quotas/abuse, billing/usage and
backup/restore receipts. Record moderation reasons with explicit owner actor
attribution; this is not independent per-moderator identity verification. Document
incidents and escalation privately. Feature disable controls participation; it does
not promise that session renewal, lookups or all provider spend stop. Emergency
infrastructure shutdown and credential compromise response require a separately
scoped procedure. Rotation must invalidate affected credentials deliberately,
preserve audit evidence and be followed by real acceptance.

Keep backup cadence, retention and recovery ownership in the approved operating
record. Do not claim unimplemented automatic deletion, complete hosted recovery,
or unattended monitoring. Production acceptance and publication remain the next
environment-dependent milestones.
