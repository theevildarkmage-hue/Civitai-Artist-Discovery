# Community API v1

The browser calls only loopback `/api/community/*`. Python obtains the existing OAuth
access token; it never returns the token to JavaScript. The eventual Edge Function
accepts `POST /functions/v1/community-v1` with an HTTPS bearer header and a JSON body:

```json
{"apiVersion":1,"operation":"recommend","artwork":1001}
```

The local adapter implements the same operation/result contract in-process. All
responses have `apiVersion: 1`; errors have `code` and a friendly `error` string.
HTTP errors from the remote adapter preserve that error vocabulary.

| Operation | Loopback transport | Request fields | Success result |
| --- | --- | --- | --- |
| `status` | GET `/api/community/status` | none | `member`, `quota`, `development` |
| `verify` | POST `/api/community/verify` | `artwork` | `imageId`, unchanged `quota` |
| `recommend` | POST `/api/community/recommend` | `artwork`, optional `idempotencyKey` | `imageId`, updated `quota`, optional `replayed` |
| `gallery` | GET `/api/community/gallery?cursor=...` | optional opaque `cursor` | `items`, `nextCursor` |
| `withdraw` | POST `/api/community/withdraw` | `artwork` | `imageId` |

`artwork` is a positive numeric ID of at most 15 decimal digits, or an exact HTTPS
`civitai.com/images/ID` or `civitai.red/images/ID` page URL (optional `www` and final
slash). No query/fragment/port is accepted in v1. Local browser POST payloads must
contain `artwork` and, for recommendations only, an optional `idempotencyKey` (16?80 ASCII letters, digits, underscores or hyphens). Identity/creator/time/quota fields are never accepted.
The Edge envelope additionally requires API version and operation and rejects unknown
fields. Shared gallery requests accept limits 1–50; the browser uses the default 24.

`quota` contains `used`, `limit` (3), `remaining`, UTC `week` and `resetsAt`. Preview
eligibility is advisory: final recommendation re-verifies and rechecks all rules
atomically. The UI uses one modal and calls recommend directly; verify remains a read-only diagnostic operation. A retry with the same key and verified member/image returns success with current quota and `replayed: true`. A different image with the same key is invalid. Keyless retries still return `DUPLICATE`. Replay rows and acceptance/audit rows commit together.

Shared gallery rows contain only canonical `imageId`, `creatorId`, recommending member
credit and `submittedAt`. Pagination is by monotonically increasing sequence, newest
first; sequence cursors are serialized as strings, not timestamps or offsets. New
submissions cannot duplicate earlier pages. Hidden/removed entries may shorten a page.
An empty filtered page with a cursor is not the end: **Load more** remains available.

The local privacy wrapper resolves fresh artwork and current viewer controls and adds
an `artwork` object only to allowed gallery rows or an allowed verification preview.
That object has canonical credit/page URLs and a verified preview. The shared service
never needs to store image binaries or arbitrary submitted preview URLs.

`GET /api/community/config` is a loopback-only capability hint for showing the explicit
development entry point. It returns no member, credentials, internal paths or artwork.

| Code | Typical HTTP status | Meaning |
| --- | --- | --- |
| `INVALID_REQUEST` | 400 | Invalid operation/envelope/pagination/body |
| `INVALID_ARTWORK` | 400/404 | Invalid reference, missing/mismatched/unavailable/unsupported artwork |
| `UNVERIFIED_OWNER` | 400 | Missing or inconsistent authoritative creator identity |
| `SELF_RECOMMENDATION` | 403 | Verified member and verified owner are the same account |
| `CONTENT_FILTERED` | 403 | Local viewer's content controls reject this artwork |
| `FORBIDDEN` | 403 | Not the author, or unavailable operator operation |
| `MEMBER_QUOTA` | 409 | Member's three accepted artworks for this week are spent |
| `ARTIST_QUOTA` | 409 | Creator's three distinct artworks for this week are spent |
| `DUPLICATE` | 409 | Canonical image ID was already accepted, regardless of status/week |
| `AUTH_REQUIRED` | 401 | No local authorization/bearer token |
| `AUTH_EXPIRED` | 401 | Invalid, revoked, expired or inconsistent Civitai identity |
| `RATE_LIMITED` | 429 | Local, shared or upstream request budget exhausted |
| `UNAVAILABLE` | 503 | Offline, timeout, controls unavailable, unexpected service response |

No OAuth token appears in a URL, browser response, database row or community error.
Ordinary response caching is disabled. Browser drafts and rendered cards are discarded
on local settings/account/content-control changes; refreshing Community always resolves
current viewer controls. Production metadata uses the established 24-hour stale/background-refresh policy; explicit refresh requests background revalidation. Fixture gallery snapshots remain explicit development metadata, while interactive fixture submissions now use live authenticated verification.

Gallery `counts.exclusions` reports overlapping reason counts (ratingRestriction, hiddenCreator, hiddenArtwork, hiddenTag, blockedUser, incompleteMetadata, other). `contentControls` counts distinct excluded records. Reconcile acceptedPage = returned + contentControls + unavailableMetadata + ownerMismatch for each page. `controls` reports active restriction totals without returning excluded artwork.
