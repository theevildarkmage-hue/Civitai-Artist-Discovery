# Community integration and stress testing

October 21 integration update: the stress harness now generates its complete synthetic
manifest in a disposable root. It does not need the interactive sample file, metadata
sampling or shutdown of port 8907. Current tests use ephemeral challenged endpoints.
The older extraction workflow below remains historical context. See the
[controlled integration report](3.0-integration-2026-10-21.md).

This follow-up replaces Community's separate rating buttons with the existing shared
`contentFilter` / `contentMenu`. Community has no rating-selection state of its own.
The existing settings API, `chooseContentRating` and Python content profile remain the
authorities. Shared filters are reachable from Community's navigation toolbar; model
filters remain scoped to personal galleries. No new rating restriction is introduced.

Content mutations clear Community cards and drafts before saving. Successful saves
reload against authoritative server controls; generation/version checks discard late
permissive responses. A same-origin BroadcastChannel also synchronizes other browser
windows/tabs without transmitting OAuth credentials. Existing navigation tabs, page
reloads and application restarts use the same persisted settings.

## Repeatable local workflow

1. Stop only the 3.0 development instance using its Close app control. The stress test
   requires exclusive port 8907 and refuses to contact/stop an occupied port's owner.
2. Extract a small metadata fixture from explicitly authorized local source data:

   ```powershell
   python scripts/sample-community.py --source '<2.x checkout>\data'
   ```

3. Run validation and render the private report:

   ```powershell
   python tests/community_backend.py
   python tests/community_safety.py
   python tests/community_stress.py
   python scripts/community-report.py
   ```

4. To inspect the metadata fixture interactively, with test reset/fault endpoints disabled:

   ```powershell
   .\scripts\dev-3.0.ps1 -DataDirectory data-test-community -UseMetadataSample
   ```

The metadata sampler uses SQLite `mode=ro&immutable=1` and `query_only`; it does not copy
either database or replay live WAL files. It reads the last checkpointed database image,
exports only bounded metadata, and records source size/mtime before and after extraction.
No credentials, prompts, account configuration, reaction actions or image binaries are
exported. The manifest and full report are ignored private development artifacts.

The inspected source had 3,462,905 archive rows and 7,633 reaction-metadata rows. The
sample has 172 records across all five ratings, including 112 reaction-history records.
Numeric owner IDs explicitly present in those records are retained as cached fixture
evidence. Archive-only records lack owner IDs, so their owner identities are explicitly
simulated and are never presented as live Civitai verification. Deleted/inaccessible/
incomplete states are injected negative fixtures because offline metadata cannot
establish current upstream status. Previews are local synthetic SVGs; canonical artwork
and artist links retain their real metadata identifiers.

## Ten members and test isolation

Fixture mode provides `DemoMember01` through `DemoMember10`, each with a distinct numeric
fixture identity, server quota and persisted contribution rows. The development selector
sets an HttpOnly, SameSite cookie; identities are independent between browser contexts.
Production mode ignores the fixture cookie and rejects identity overrides. No simulated
identity changes a real OAuth credential or contacts Civitai/Supabase.

The managed harness launches this clone's server on 8907 with an explicit `data-test-*`
root and challenge nonce. It verifies the nonce and data-root identity before mutations.
Test-mode POSTs require that nonce. Reset, snapshot, hidden controls, fixed UTC clock,
removed artwork, outage and lost-response injection require all of development mode,
fixture mode, test mode, an isolated data root and the nonce. They are unavailable in the
ordinary development launcher and Supabase adapter. The test clock persists through
restarts; concurrent-race assertions require correct counts regardless of which request
wins the race.

`tests/test_safety.py` is imported before network activity by the existing script suite.
It registers only owned fixture/static servers or this clone's isolated subprocesses,
rejects protected ports before network access or process launch, refuses unknown/live
destinations and exited owners, and blocks unmocked browser external traffic. It gives
directly invoked tests a fresh default data directory. Automated test processes cannot
use the 2.x installation or a normal development data root. The stress server also
disables outbound connections. Original-link browser navigation is fulfilled offline.

## Results and evidence

The complete local report is generated at `reports/community-stress-report.md`, with
full IDs/results, all ten members, both baseline runs, rejected requests, per-scenario
database/audit snapshots, artist counts, concurrency outcomes, safety checks, browser
errors and limitations. Machine evidence is `reports/community-stress.json`; guarded
legacy outcomes are `reports/community-guarded-regression.json`. Screenshots are
`reports/community-ten-desktop.png` and `reports/community-ten-mobile.png`.

The tested baseline accepts exactly 30 distinct recommendations through the API and,
after reset, another 30 through the real UI. Every member's fourth is rejected. All
30 appear through pagination with permissive settings and correct credits. The suite
checks 22 adversarial scenarios against persisted records/audit, not only responses.
All 84 original regression scripts pass under the guard, with a legacy temporary-root
prefix corrected to satisfy its isolation rule. Backend tests cover 19 cases and the
dedicated safety tests cover six more. The actual Edge handler's offline transport test
also passes; no cloud execution is implied.

Browser checks include all 30 preview image loads, ten identities, credits, original
link navigation, pagination, shared filters, delayed stale responses, a second browser
tab, reload, restart, mobile layout, empty states, rejection messages and lost confirmation
recovery. A seeded isolated personal archive remains usable during Community outages.

The stress tests found and fixed a disabled confirmation retry, submission throttling
being consumed by routine reads, stale pagination, and stale draft/response handling.
Local reads now have a separate bounded budget; mutation/verification throttling remains.
A lost response after a successful database commit is reconciled through authoritative
quota and duplicate detection: it is one acceptance, never a second debit on retry.

No 2.x installation/data, cloud resources, public deployment, GitHub default branch,
release or remote branch was changed. Real Civitai ownership/availability and actual
PostgreSQL locking/RLS/Edge runtime remain separate production integration checks.
