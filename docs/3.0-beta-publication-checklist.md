## Required evidence before requesting publication approval

1. Resolve hosted operator enrollment/MFA and all master-task deployment gates.
   Complete actual owner-authorized Civitai authentication, scoped hosted acceptance,
   direct ordinary authenticated denials and final disabled policy/hash checks.
2. Complete Linux desktop execution and packaged Windows fresh OAuth, restart,
   upgrade/rollback and live hosted acceptance. Fixture screenshots are not this
   evidence. Close the privacy/contact/retention, backup custody and on-call gates.
3. Review exact private source commit and all seven migration/function hashes.
   Keep staging as staging; do not point testers to an unaccepted backend.
4. Prepare a clean publication snapshot on an explicitly approved publication line.
   Private `3.0` and `development/3.0` have divergent histories; do not merge/push
   private history, runtime files, archives or reports to save effort. Review the
   full source/history for credentials and machine paths. Current publication
   branches must remain unchanged until that separate approval.
5. Once the approved publication commit exists, rebuild from that exact clean
   commit with the pinned patched Python/OpenSSL/PyInstaller/dependencies. The
   current local private-commit artifact is not silently retagged as that snapshot.
6. Generate final `release-identity.json`, ZIP, SHA256SUMS and release manifest.
   The identity must contain applicationId CivitaiDiscoveryBeta, channel beta,
   version 3.0.0-beta.1, matching tag/commit, sourceDirty false and preview false.
   Attach Windows portable folder ZIP and checksums, Linux guide, beta README,
   release notes, privacy and rollback instructions. Do not include backups or data.
7. Inspect the actual frozen archive and rerun packaged acceptance against those
   exact bytes. Record checksums and source commit in the approval request.

## Reproducible local preparation commands

```powershell
./scripts/build_exe.ps1 -OutputRoot reports/<review>/windows -PythonExecutable <patched-python>
python -B scripts/inspect-production-package.py --package reports/<review>/windows/dist/CivitaiDiscoveryBeta --output reports/<review>/package-check
python -B scripts/validate_packaged_updater.py reports/<review>/windows/dist/CivitaiDiscoveryBeta --browser
python -B scripts/prepare-beta-artifacts.py --package reports/<review>/windows/dist/CivitaiDiscoveryBeta --output reports/<review>/release
python -B scripts/prepare-community-candidate.py --project-ref aibelmhucizupzvvhdvf --schema-model release --output-directory reports/<review>/proposal
```

Build seed/timestamps are pinned to the source commit. This improves repeatability;
byte-identical builds on independent machines are not claimed without comparison.
Source-mode Linux uses the separately reviewed update script and a private data
directory. A local candidate must never masquerade as an already approved release.
