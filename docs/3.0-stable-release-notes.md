# Civitai Artist Discovery 3.0.1

Prepared stable Windows maintenance release; assets become available after
separate owner-approved publication. Production Community remains public; Registry
remains disabled. No database migration or additional account setup is required.

## Fixes

- Community shows a clearer new-artwork notice with an inline Refresh action,
  counting eligible recommendations while retaining the current cards and scroll.
- Existing Civitai reactions are highlighted on Community artwork, including
  account changes and delayed network responses.
- Missing artwork no longer makes optional reaction reads fail as a batch;
  unavailable artwork cannot trigger a reaction write.
- Time Machine previews use their own saved image records, fixing failures for
  images absent from Daily Gallery while retaining content controls.
- Restarting stable source preserves Production mode, port and profile.
- Recommendations support PG, PG-13, R, X and XXX images/videos. If only your
  rating selection hides the pasted artwork, you can explicitly recommend it
  without loading its preview. Your gallery still follows your viewing settings.
  Hidden tags/artworks/creators, blocks, availability, ownership and quotas remain
  enforced. See [the rating policy](3.0-community-rating-policy.md).

- Windows update helpers no longer load developer identity-audit tools during
  startup, fixing the new failure at long staging paths. Local diagnostics keep
  their privacy and credential redaction.
- Beta users can manually preserve local settings/databases without a new bridge;
  the bundled recovery script excludes credentials and Development cloud sessions.

## Known Windows limitation

A pre-existing IDNA codec startup error can occur in very deeply nested folders
(observed with a 253-character executable path in both public 3.0.0 and this
candidate). Standard portable layouts and actual automatic upgrades pass; this
release does not claim unrestricted deep-path operation or change Windows settings.
See [tested installation and recovery guidance](3.0-stable-installation.md).

## Install or update

Windows users should use `CivitaiArtistDiscovery-3.0.1.zip` from the
[3.0.1 release](https://github.com/theevildarkmage-hue/Civitai-Artist-Discovery/releases/tag/v3.0.1).
The existing stable updater can discover this release. For a manual update, close
the app, back up your matching application/profile, and replace application files
while preserving the existing `data` directory. Extract the complete package;
copying the executable alone is insufficient. See [installation and rollback](3.0-stable-installation.md).

Windows builds are unsigned. Linux source remains experimental: update to this
release or current main and launch with `--stable` using the
[source instructions](3.0-linux-stable-source.md). Source launches now identify
stable as 3.0.1. Plain source launches retain the beta/Development defaults.
No new beta release is part of this stable maintenance release.

Credential isolation and the signed identity architecture are retained. Privacy
and deletion contact: [theevildarkmage@gmail.com](mailto:theevildarkmage@gmail.com).
Report general problems through [GitHub Issues](https://github.com/theevildarkmage-hue/Civitai-Artist-Discovery/issues);
use [private vulnerability reporting](https://github.com/theevildarkmage-hue/Civitai-Artist-Discovery/security/advisories/new)
for security issues. Never attach credentials or private profile data.

# Civitai Artist Discovery 3.0.0

Prepared stable Windows release; unpublished until explicit owner approval.
Production Community and Registry remain disabled during candidate acceptance.

## Community, with one Civitai sign-in

When Production public access is activated, signing in with the built-in Civitai
application automatically enrolls your verified account in Community. There is no
invitation, separate registration or second Community login. Community is the
default tab after sign-in; refreshing preserves the tab you selected.

Recommend eligible public artwork to spotlight another artist. Each member can
recommend three artworks per UTC week, and each artist can receive three per UTC
week across all members. Duplicates and self-recommendations are rejected.
Withdrawal or moderation removes an entry from the active feed while preserving
quota and audit history. Recommendations leave the feed after seven days.

Community and Daily Gallery share artist cards, carousels, metadata caching,
rating/hidden-tag controls, thumbnails, details and existing video behavior.
Community receives accepted recommendation IDs from the service; browsing does
not trigger a separate hosted artwork-verification pipeline. Unknown required
tag checks continue to fail closed and offer retry.

Daily Gallery remains local and usable when Community is unavailable. Civitai API
access/refresh credentials stay on the user's computer. The hosted service verifies
a signed identity proof and uses separate Discovery sessions/device authorization.
See the [privacy notice](3.0-privacy.md) for membership, recommendations, optional
registry collection, retention boundaries and request contacts.

## Credential isolation correction

Authenticated diagnostic search rejects unsafe origins and redirects before sending
its key while retaining approved searches, filters, pagination and retries. Daily
Gallery still uses the default v1 feed. Unexpected refresh-response assertions are
discarded before local storage; signed identity verification and Discovery device/
session authorization remain unchanged. Permanent source and dual-frozen-channel
credential-boundary tests enforce this behavior.

## Install and update

The canonical stable asset is `CivitaiArtistDiscovery-3.0.0.zip`. Its exact source
commit and SHA-256 accompany it in `release-manifest.json` and `SHA256SUMS.txt`.
Extract the complete `CivitaiArtistDiscovery` folder, including `_internal`, into
a writable location. Windows 10/11 is the packaged acceptance target; the build
is unsigned. Linux source support remains experimental and owner-waived.

Publishing a non-prerelease `v3.0.0` with the canonical asset and GitHub SHA-256
digest makes it eligible for the existing 2.2.1 stable updater. It does not make
the unpublished candidate discoverable today. Beta.13 users need the separately
approved beta.14 bridge before stable graduation. Existing stable users are not
offered a beta release.

See [installation, upgrades and rollback](3.0-stable-installation.md). Keep a
protected copy of the matching old application and profile before upgrading;
do not run two versions against the same profile. Community server history is
independent of local application rollback.

## Candidate acceptance and launch gates

The source includes a forward-only correction that creates/updates the Community
member row during verified public identity enrollment, before any recommendation.
It is tested on disposable infrastructure and deployed while Production remains
disabled. Public activation still requires Publish. Existing policy, quotas and
permissions are retained. No Development data or sessions transfer to Production.

Live public enrollment and release-download visibility remain launch-time checks.
The current disabled Production environment is not evidence that these live gates
have completed. [Launch and disable sequence](3.0-public-launch.md).
